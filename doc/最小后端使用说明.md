# 最小后端使用说明

当前双方职责为：我方负责后端、Web 管理后台、接口契约和接口联调支持；甲方另行开发学员前端，并按[题库 Excel 模板](题库导入模板-v1.xlsx)及[整理说明](题库整理与交付说明-v1.md)交付正式题库。甲方前端团队的接入范围及当前接口能力见[后端对接说明](前端团队后端对接说明-v1.md)。

本文文件名沿用最小后端阶段，现已更新为当前题库操作说明。题库、微信身份、永久权益、试学、激活码、学习同步、随机续学及支付服务端均已实现；业务管理操作见[模块说明](modules/)，学员接入见[联调手册](学员接口联调手册.md)。仓库历史小程序仍读取演示数据，后台发布不会自动更新它；正式学员前端由甲方开发。

用户已确认选定账号完成备案、虚拟支付、Apple IAP和成员加入，AppID／OfferID已确定。当前先按[本机准备说明](本机微信与支付联调准备-v1.md)补齐配置并核对旧库迁移，保持支付新销售关闭；这不等于真实登录／支付已验收。已有数据库先备份，再执行更新和迁移，勿把首次安装流程当作无备份升级。

最小题库阶段的历史测试与浏览器结果见[早期验收记录](最小后端验收记录.md)，其中“尚未实施”及54项测试仅描述当时版本，不代表当前能力。当前后端验收以[阶段记录](后端阶段验收与交付记录-v1.md)为准。早期题库界面参考：[导入预检截图](后端验收截图/导入预检.png)、[题目预览截图](后端验收截图/题目预览.png)。

## 1. 第一次启动

在项目根目录打开 PowerShell，依次运行：

```powershell
.\backend\setup.ps1
.\backend\start.ps1
```

`setup.ps1` 在 `backend/.venv` 安装锁定的依赖，生成本机随机密钥 `.env`，建立数据库、权限组和演示草稿，然后提示你设置管理员用户名和密码。输入密码时终端不显示字符是正常情况。已有管理员时不会再创建；重复执行不会覆盖已有题目或权限组。

脚本还初始化缺失的六个业务权限组和单商品，保留已有价格与权限。已有`.env`不会被首次初始化脚本重建；旧版本缺少学员加密／微信／支付配置时，按本机准备工具补齐，不删除原文件重新生成。平台账号确认不会使商品自动同步或支付自动开启。

后台地址：<http://127.0.0.1:8000/admin/>。保持启动终端运行；需要关闭时按 Ctrl+C。第二次启动只需运行 `start.ps1`。端口冲突时可执行 `start.ps1 -Port 8001`，再打开对应端口。

依赖独立于小程序的 npm 环境。本机使用 Python 3.14.7，精确版本见 `backend/requirements.txt`。如在另一台电脑使用已安装的 Python 3.13，可执行 `setup.ps1 -PythonVersion 3.13`；不要共用两个 Python 版本的虚拟环境。

如需分步运行：

```powershell
cd backend
# setup.ps1 已建立 .venv 和 .env 后：
.\.venv\Scripts\python.exe manage.py migrate
.\.venv\Scripts\python.exe manage.py seed_demo
.\.venv\Scripts\python.exe manage.py setup_roles
.\.venv\Scripts\python.exe manage.py setup_business_roles
.\.venv\Scripts\python.exe manage.py seed_product
.\.venv\Scripts\python.exe manage.py createsuperuser
.\.venv\Scripts\python.exe manage.py runserver 127.0.0.1:8000
```

`setup.ps1 -SkipAdmin` 可用于自动检查，只跳过交互创建管理员；使用后台前仍需自行执行 `createsuperuser`。忘记密码时，在本机执行 `manage.py changepassword 你的用户名`，无须删除数据库。

## 2. 先体验一个完整流程

1. 登录后台，进入“题目”。初始化后有 16 道演示草稿、8 个文学分类、23 个真实篇名目录；原型的 2 条“待补充篇目”没有导入。
2. 打开一道题，查看题干、答案和预览。保存只更新草稿。
3. 在列表中选择题目并执行发布操作。只有具备发布权限的账号能执行。
4. 在同一个浏览器打开 <http://127.0.0.1:8000/api/v1/questions/>，此时能看到已发布题目。
5. 回后台修改题干或答案并保存，再刷新接口：仍显示之前发布的版本。
6. 再次发布后，接口才显示新内容；下架后，该题不再进入列表，详情返回 404。

题目 ID 是这道题的固定编号。修改内容、调整排序、发布、下架和重复导入都保留它；换成另一道题应创建新 ID。旧发布修订只读保留，首版不做回滚操作页面。

文学题使用 `literature` 来源、文学分类及 `fact` 题型；文言题使用 `classical` 来源、篇目及 `fact/word/translation`。答案按顺序对应题干的 `{{0}}`、`{{1}}` 等占位符；编号从 0 连续开始，不能漏答案或多填未使用的答案。

分类和篇目只做维护、排序和停用。仍有已发布题目引用时，须先下架相关题目才允许停用。不提供题目、分类、篇目和发布历史的后台物理删除入口。

## 3. 用 Excel 批量导入

在题目列表进入“导入”，先下载模板。模板下载地址为 `/admin/content/question/import-template/`，需要编辑和导入权限。

模板包含“题库”“填写说明”“例题参考”“分类与篇目”工作表。**只把要导入的题目填到“题库”表**；其他表供参考，不会被当作题目导入。

| 列 | 填写规则 |
| --- | --- |
| 题目ID | 必填，英文字母/数字/连字符/下划线，不超过 64 字符且区分大小写；同题保持同一 ID |
| 来源 | `literature` 或 `classical` |
| 分类ID | 文学题必填，使用后台已有分类 ID |
| 篇目ID | 文言题必填，使用后台已有篇目 ID |
| 题型 | `fact`、`word` 或 `translation` |
| 标签 | 题卡说明，例如“文学常识”“重点字词” |
| 排序 | 非负整数；越小越靠前 |
| 题干 | 含 `{{0}}` 等占位符的文字 |
| 答案1…答案7 | 分别对应 `{{0}}`…`{{6}}`；可连续增加到答案32，未使用的尾部列留空 |

流程为：上传 XLSX → 查看新增、修改、无变化和错误行 → 无错误时确认 → 写入草稿 → 检查并发布。题目 ID 已存在表示更新，不按相似题干或 Excel 行号匹配。首次导入新题还需新增题目权限。

一行有错误就不会提交整批数据。预览之后若同题被别人修改，确认会要求重新预检；预览有效期为 30 分钟。重复导入同一文件不重复创建题目，导入不会改变发布状态或直接覆盖已发布版本。

限制：仅 XLSX，文件不超过 5 MiB、题目不超过 5000 行、答案不超过 32 列；解压数据上限 50 MiB。拒绝公式单元格和不符合模板的文件。不支持 Word、PDF、图片识别或任意第三方 Excel 自动转换。

后台“导出”下载当前草稿，保留固定 ID。文本单元格不会作为 Excel 公式执行，可修改后重新导入。导出内容供有权限的编辑维护，不是学员下载接口。

## 4. 账号与操作记录

默认提供三个可组合的权限组：

| 组 | 能力 |
| --- | --- |
| 题库查看 | 查看后台内容、发布历史及对应查询接口 |
| 题库编辑 | 查看、新建/修改分类篇目与题目、模板下载、导入草稿 |
| 题库发布 | 查看、发布和下架；不自动拥有编辑权限 |

由超级管理员创建其他账号，勾选“工作人员状态”，分配一个或多个组。一个人可同时拥有编辑和发布权限；首版不强制双人审核。账号须同时为启用状态、工作人员并拥有对应权限，普通登录状态不足以访问题库 API。

商业后台另有“业务查看、学员启停、商品运营、激活码管理、权益撤销、支付核查”六组，按职责分配，详见[运维手册](生产部署与运维手册.md)。学员启停不授用户权限编辑，支付核查不授手工改订单为已付。两项初始化命令只创建缺失组，不修改已有组、不自动给用户分组。

免费页题数在“学习配置”设置，范围1～100，初值20；首次保存需要`content.add_learningconfiguration`，后续修改需要`content.change_learningconfiguration`。普通题库编辑／发布组不自动具有这两项配置权限，由可信管理员单独授权。文言同篇目的字词／翻译共用免费集合，不各赠一页。

管理员可在“日志记录”查看后台修改、导入、发布和下架记录。操作记录和发布历史不提供后台删除入口。不要给题库编辑人员分配用户管理或超级管理员权限。

## 5. 查询接口

除健康检查外，下面接口都需要同站后台Session和相应查看权限，仅供后台人员；不提供创建、编辑、删除操作。已实现的学员接口使用独立`/api/student/v1/`及Bearer，公开目录／试学允许匿名，不能把下面后台接口交给学员调用。学员字段和错误码见[联调手册](学员接口联调手册.md)。

| 方法与路径 | 参数与含义 |
| --- | --- |
| `GET /healthz` | 匿名返回 `{"status":"ok"}`，仅说明应用可响应，不返回配置，也不代替数据库监测 |
| `GET /api/v1/categories/` | 启用的分类；`page`、`page_size` |
| `GET /api/v1/articles/` | 启用的篇目；`page`、`page_size` |
| `GET /api/v1/questions/` | 已发布题；`source`、`categoryId`、`articleId`、`type`、`page`、`page_size` |
| `GET /api/v1/questions/{id}/` | 已发布单题；无权或未发布的内容不会返回 |

列表格式统一为 `count、next、previous、results`；默认每页 20，`page_size` 允许 1–100。按已发布内容的排序值和稳定 ID 排列。未知参数、重复参数、空值、非法枚举或超出允许范围的页大小返回 400；越界页返回 404。格式合法但不存在的分类/篇目筛选返回空列表。

在登录后台的同一个浏览器，可打开：

```text
http://127.0.0.1:8000/api/v1/questions/?source=classical&articleId=quanxue&type=word&page_size=5
```

题目字段示例（对应题目发布后才会出现）：

```json
{
  "id": "word-ri",
  "source": "classical",
  "categoryId": null,
  "articleId": "quanxue",
  "type": "word",
  "tag": "重点字词",
  "stem": "“君子博学而日参省乎己”中，“日”的意思是{{0}}。",
  "answers": ["每天"],
  "sortOrder": 9,
  "revision": 1
}
```

未登录、非工作人员、停用账号或缺少查看权限返回 403；有查询权限但使用写方法返回 405。浏览器会话失效时重新登录后台即可。CSRF 防护保持开启，不用关闭它来调接口。

## 6. 测试与数据保管

```powershell
cd backend
.\.venv\Scripts\python.exe manage.py check
.\.venv\Scripts\python.exe manage.py makemigrations --check --dry-run
.\.venv\Scripts\python.exe scripts/verify.py --database sqlite
# 回到项目根目录后检查现有小程序
cd ..
npm test
npm run check
npm run check:native
```

本地数据库默认是`backend/db.sqlite3`，已有库升级前用`manage.py backup_database --output <未使用的私有备份路径>`创建一致快照，工具拒绝覆盖旧备份；具体可复制命令见[本机准备说明](本机微信与支付联调准备-v1.md)。恢复先验证到独立新库，保留原库，详见[运维手册](生产部署与运维手册.md)。`.env`、加密密钥与数据库须妥善配套保管；数据库、原码CSV、备份和私有档案不纳入Git。

支付持久任务与补偿命令已实现；实际调度部署见[P10说明](modules/P10-支付同步与补偿.md)与运维手册，本轮离线本机诊断不自动联网查单或发货。过期导入临时文件按导入流程清理；清理`.local/imports`会使未确认预检失效，不影响已保存题目。

## 7. 已有业务能力与后续接入

- 微信学员身份、永久权益、试学、激活码、学习同步、随机轮次／续学和官方虚拟支付服务端均已交付；甲方前端按正式学员接口接入，后端原后台Session保持独立。
- 原码一次下载、领取后启用；已激活不消耗新码；误发撤销与退款仅影响对应来源。后台不提供手工改订单为已付或随意发放付款权益入口。
- 学习状态使用稳定题目ID、版本号和幂等键；甲方前端处理401、403、409、失权及跨设备冲突，不自行覆盖服务端状态。
- PostgreSQL16真实并发、备份恢复及SQLite→PG迁移演练已有CI证据；实际本机仍可用SQLite，SQLite运行不代替并发验证。生产切换须按运维手册迁移数据，改环境变量不会自动搬迁。
- 媒体、新题型、学员Web、自助退款、账号转移与旧匿名演示记录迁移不在当前范围；不重新把已确认规则列为问卷待定。

本机启动只监听回环地址，Django`runserver`不作为公网方案。当前先完成P13配置与离线诊断，支付销售保持关闭；真实微信、Android／iOS付款、HTTPS回调和甲方前端仍需联合验收，生产环境另行交付。
