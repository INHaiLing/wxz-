# 学员前端接口联调手册 v1

本项目交付 Django 后端与管理后台，学员小程序由甲方开发。机器契约见 [student-v1.openapi.json](api/student-v1.openapi.json)；接口前缀 `/api/student/v1/`，路径末尾保留 `/`。本文示例均为测试数据，不含可用令牌、激活码或真实密钥。

用户已确认选定账号完成备案、虚拟支付、Apple IAP和开发成员加入，AppID／OfferID已确定；公开文档脱敏，实际标识在私有配置。当前先做[本机配置与联调准备](本机微信与支付联调准备-v1.md)，不表示真实登录／付款已验收，也不自动开启任何支付新销售开关。

## 启动与检查

后端安装、管理员和题库维护按仓库 README 操作。开发使用 `http://127.0.0.1:8000`，真机与生产须配置 HTTPS、微信合法请求域名和对应后端环境。学员接口只收发 JSON；后台 `/api/v1/` 使用管理员 Session，不能给学员使用。

在 backend 目录运行：

```powershell
.venv/Scripts/python.exe manage.py check_student_contract --settings=config.test_settings
.venv/Scripts/python.exe manage.py test contracts --settings=config.test_settings
```

接口变更后，审查 `contracts/document.py` 的响应定义，执行 `write_student_contract` 更新 JSON，再运行检查。命令不会创建假业务数据或对外假接口。自动化测试只在临时库中替换微信／支付外部调用，真实渠道及设备联调仍须单独完成。

## 登录与会话

1. 前端调用 `wx.login` 获取一次性 code，将 `{code}` POST 到 `auth/wechat/`，该请求不发送旧 Bearer，不传 openid、AppID、session_key 或密钥。
2. 后端用服务端配置向微信换身份，返回 `{token,expiresAt,user:{id}}`。保存随机 token，后续个人接口发送 `Authorization: Bearer <token>`。
3. Bearer 技术默认有效 7 天；401 时停止该次个人请求，清理旧 token，重新 `wx.login` 换取会话，再读取当前状态。禁止把401转成匿名继续调用个人接口。
4. `POST auth/logout/` 撤销当前设备会话，204 无正文。其他设备会话不受影响；账号停用后所有设备均失效。

公开目录／试学可省略 Authorization；一旦显式提供错误、过期或已撤销 Bearer，公开接口同样返回401。后台 Cookie 不能替代学员身份。返回 token 不能上传日志、埋点、URL或提交到 Git。

购买前先用 `wx.checkSession` 确认微信会话；需要时重新 `wx.login`。后端 Bearer 的7天期限不能证明微信 session_key 仍有效，签名使用本次登录的服务端加密会话。已进入支付处理的订单应查询原订单，不能因重登或客户端取消直接另行开通。

## 目录、题目与免费试学

先 GET `config/` 读取 `pageSize`、`dailyTarget`、可空 `examDate`。页容量后台设置1～100、初值20；不要写死每页题数，不发送 `page_size`、`limit` 或 `ordering`。考试日期为空时不显示虚构倒计时。

| 场景 | 请求 |
| --- | --- |
| 文学目录 | GET categories/?page=1 |
| 文言篇目 | GET articles/?page=1 |
| 文学题目 | GET questions/?source=literature&categoryId={id}&page=1 |
| 《劝学》全部题型 | GET questions/?source=classical&articleId=quanxue&page=1 |
| 同篇目字词／翻译 | 上一请求增加 type=word 或 type=translation |
| 已授权单题 | GET questions/{id}/ |

文学使用 categoryId；文言每篇文章使用 articleId。不能同时传二者，同一参数只能出现一次。文学只支持 fact，文言沿用 fact／word／translation。

免费集合先从该文学分类或文言篇目全部已发布题中统一排序取前 pageSize 道，再按 type 筛选；切换字词／翻译不会多给一页免费题，可能出现某题型0道免费题。列表 `count` 是当前可读取数；`access.totalCount` 是该筛选范围已发布总数，`restrictedCount` 表示受限量。目录与计数不包含草稿。

列表返回 `{count,next,previous,results,access?}`。`next/previous` 可为空，也可能是相对地址（例如订单列表的 `?page=2`）；相对地址按当前列表请求路径解析，完整地址只能使用本项目配置的后端域名。客户端跟随后端分页地址，不拼接扩大容量。无效页404。后端题干使用 `{{0}}`、`{{1}}` 对应 `answers[0]`、`answers[1]`；`revision` 为发布修订号，`id` 为稳定题目身份。草稿修改不会影响前端，重新发布后顺序题读取新版。

试学结束仍需继续时，读取 products/ 和本人 me/entitlements/。403 `ENTITLEMENT_REQUIRED` 提示开通权益；不要下载收费正文后仅在前端遮盖。永久权益是全题库，不按文章累加天数；后台调整免费容量或下架后每次请求重新判断权限。

## 权益与激活码

`GET products/` 返回全题库单商品。`priceFen` 单位是分，初值1000分即10元；展示换算成元，订单提交只发送商品ID，不能由前端提交价格或期限。`permanent:true`、`expiresAt:null` 为永久规则。

`paymentChannels.android/ios` 是当前渠道是否可用；`purchaseAvailable` 表示至少一个渠道可用。前端仍须按本设备渠道判断，不能因为 Android 可用就放开 iOS。`PLATFORM_SYNC_REQUIRED`、`PRODUCT_DISABLED`、`PAYMENT_CHANNEL_UNAVAILABLE` 显示暂不可购买；后台改价后的平台同步未完成会阻止新支付。

Apple 支付仅支持正式环境（`env=0`），不支持沙箱，商品价格至少 100 分（1 元）；不满足时后端将 `paymentChannels.ios` 置为 false，并在下单和支付准备时返回 503 `PAYMENT_CHANNEL_UNAVAILABLE`。Android 的沙箱与正整数分金额规则保留。甲方前端须另外核查 iOS 15 及以上、微信 8.0.68 及以上和中国大陆 App Store 账号条件；默认 iOS 渠道关闭，完成真实 Apple 付款与退款验收后才能启用。[微信官方说明](https://developers.weixin.qq.com/miniprogram/dev/platform-capabilities/business-capabilities/virtual-payment.html)

`GET me/entitlements/` 返回 `{scope:"all_chinese",active,permanent,expiresAt:null}`，以 active 为当前授权依据。撤销或退款只影响对应来源，其他有效来源仍可能使 active 保持 true。

兑换调用 `POST activation/redeem/`，JSON `{code}`，并带 `Idempotency-Key`。原码永久不过期，但须管理员生成、确认CSV已保存并启用后才能兑换。正常返回 `{redemptionId,redeemedAt,entitlement}`。

已激活返回409 `ALREADY_ACTIVATED`，文案“已激活”，新码不消耗。`PURCHASE_IN_PROGRESS` 提示“购买处理中”，不能消耗新码。未领取、禁用、无效或他人已兑码不可用。原成功请求重试保留 key 和 code，返回历史兑换ID及当前权益；撤权后旧重放不会重新激活，已兑码不能复用。

线下收款由甲方自行处理，平台仅兑换激活码；线上支付使用小程序内官方虚拟支付，不使用扫码支付。

## 学习状态、模式与统计

进入题目时 GET `me/questions/{id}/state/` 获取本人 `{questionId,favorite,mastered,version}`。可访问题无记录返回 false／false／0且不写库。新设备应先读取状态，再展示收藏／掌握按钮。受限或下架后，本人已有记录仍可读且没有题正文；无本人记录的受限题不能读取。

更新使用显式 PUT `{favorite?,mastered?,baseVersion}`，至少一个 boolean，带幂等键；禁止发送 toggle 或字符串"true"。收藏与掌握互不改变，取消不删除学习历史。

```json
{"favorite":true,"mastered":false,"baseVersion":1}
```

无权时可以取消本人已有收藏／掌握，但不能新增 true。`GET me/favorites/` 分页本人全部收藏状态；可访问项返回当前发布 `question`，受限／下架项 `question:null`，仅保留已知 state 和通用 `unavailableReason`。保留占位和取消操作，不展示收费题干、答案或猜测旧内容。

`GET/PUT me/preferences/` 保存 `mode:"writing"|"reciting"` 与 dailyTarget。默写由前端隐藏答案、展示占位线；背诵可展开答案。模式改变不更新题库、不自动标记掌握。PUT 至少一个偏好字段，携带 baseVersion／幂等键；未设置过偏好时目标采用后台默认，保存后后台默认变化不会覆盖本人目标。

`GET me/statistics/` 返回 totalQuestions、masteredQuestions、masteredPercent、todayQuestions、studyDays、completedArticles、dailyTarget。分母为全部当前有效已发布题；非空文言篇目的全部当前题掌握才完成。今日活动按服务端上海日期 false→true 首次掌握去重，同日取消后再掌握仍只计一次；不能自报日期补刷统计。下架不删除历史学习天数。

## 随机轮次与续学

登录后 `POST practice/rounds/` 带 `{source,categoryId?/articleId?,type?,mode}` 和幂等键，201返回轮次元信息。type为空代表全部题型。轮次只从当前可访问题创建，单轮最多10000道；题序、分组容量和修订固定，后续不会自动加新题或重新洗牌。

`GET practice/rounds/{roundId}/groups/{groupIndex}/` 的组号从1开始，返回 results 与 skipped；skipped 只含 position／原因。每次读取重新授权，失权、下架、篇目或题型变更会跳过，不能用旧轮次绕过免费集合。正文仍用创建时旧修订，顺序题则用最新发布修订。

`GET me/resume/` 返回 `{version,resume,valid,reason,start}`；没有断点时 resume/start为空。`PUT me/resume/` 提交类型化范围、mode、questionId、baseVersion；随机续学须同时提供 roundId 和 groupIndex；禁止保存任意页面路由。前端自行将类型化状态映射到页面。

失效断点 valid=false 时显示原因，若 start 非空，可从该可访问位置继续；不能直接进入旧收费题。PUT返回历史resume与current，旧请求重试只回历史且不覆盖新设备的位置。续学mode可以改变，不改原轮次mode或个人偏好。

## 线上订单与支付

支付配置与平台商品同步就绪后，流程为：

1. `POST orders/`：`{productId,channel:"android"|"ios"}`＋幂等键，201返回本人 order 和当前 entitlement，金额、永久规则已固定；本地 created 订单尚未签发参数时不阻止兑换。
2. `POST orders/{id}/payment/`：空JSON `{}`＋新的幂等键，返回 `{order,payment,entitlement}`。渠道在创建订单时确定，不能再传 platform、价格或期限。签发参数前后端持久化开通占位，进入 preparing 后不允许其他新订单或兑换并发开通。
3. payment 为 null 表示原请求已经进入其他状态，应刷新 order 和 entitlement。正常 payment 包含 mode、signData、paySig、signature：signData 是签名覆盖的精确字符串，必须原样传 `wx.requestVirtualPayment`，不能 JSON.parse 后重新 JSON.stringify、改字段顺序或修改金额。
4. 微信客户端 success／cancel／fail 只代表客户端观察；success 后调用后端 `POST orders/{id}/query/`（空JSON `{}`＋幂等键）查询，并读取 order／me/entitlements/。每次新查单用新键，同次网络重试保留原键。只有后端确认并发放来源后才显示已激活，不能自行 PUT 付款成功或依回调发权。
5. preparing、paid 等处理中状态保留原订单，按限频适度查询；429等待后再查。客户端取消、页面关闭、本地超时或暂查不到不能释放占位。只有平台确认最终未付款状态才释放；refund／review 由后端消息与查单状态机处理。

`GET orders/?page=1` 和 `GET orders/{id}/` 只返回本人订单，其他账号404。历史成交价不随商品改价变化；退款仅撤销本订单的支付来源，其他有效来源可能继续提供访问。前端不得自动重建旧订单冒充退款已复购。

iOS服务端销售开关默认关闭，表示该后端尚未开放新购买；平台Apple能力已由用户确认开通，两者不能混淆。本轮本机准备保持支付总开关和Android／iOS新销售关闭。iOS购买仍需正式环境0、至少100分、对应商品同步和完整私有配置，之后单独完成真机验收再受控启用。`purchaseAvailable=false`或`PAYMENT_CHANNEL_UNAVAILABLE`不能直接解释成“小程序平台未开通”。

当前Apple退款询问消息记录为待核查并返回非成功响应，不自动代表同意或拒绝退款；须在真实渠道验收核对实际消息与官方不确定流程。类目适用性、平台商品、真实支付及服务器域名仍按实际环境验证；早期截图中的待申请／未备案不再代表当前账号，本文不声明我方已完成外部审核或真机验收。

## 幂等、409和失败处理

| 返回 | 前端处理 |
| --- | --- |
| 400 VALIDATION_ERROR／IDEMPOTENCY_KEY_REQUIRED | 修正字段，键8～128位ASCII字母数字或 ._:-；不反复重试坏数据 |
| 401 AUTH_REQUIRED／INVALID_TOKEN／WECHAT_CODE_INVALID | 清理旧身份，wx.login重新换会话；公开请求省略非法头 |
| 403 ENTITLEMENT_REQUIRED | 重新查权益，提示开通；已有受限记录仍可取消 |
| 404 NOT_FOUND／NO_QUESTIONS | 提示内容或范围不可用，不枚举其他用户数据 |
| 409 VERSION_CONFLICT | fields.current是本人当前状态，保留数字版本和布尔值；刷新展示后用新key和当前版本发起新操作 |
| 409 IDEMPOTENCY_CONFLICT | 相同键已用于不同载荷；停止该重试，新业务动作使用新键 |
| 409 ALREADY_ACTIVATED | 显示“已激活”，刷新权益；新码不消耗 |
| 409 PURCHASE_IN_PROGRESS／PAYMENT_ALREADY_PREPARED | 查原订单，不消费激活码或创建替代开通 |
| 429 RATE_LIMITED | 按后端限制退避，避免循环并发轮询 |
| 503 微信／配置／支付不可用 | 保留用户上下文，稍后重试或提示管理员检查配置；不能展示成功 |

网络重试成功写请求应保留原 key／载荷／baseVersion；失败业务事务通常不记成功记录。每次新的业务动作产生新key，同一键不能改用另一题或载荷。历史成功重放可能不是当前状态，题目GET／权益GET及续学current用于刷新；撤销后的旧请求不会重新应用。

统一可处理业务错误为 `{error:{code,message,fields?},requestId}`，响应头 X-Request-ID 可用于提供给后端排查。未知服务器错误不能视作业务成功，保存脱敏请求ID与操作类型即可；不记录Authorization、码、签名参数或密钥。接口只定义业务GET／POST／PUT，框架生成HEAD／OPTIONS不作为学员业务调用。

## 交付与真实联调待办

自动化已经可以验证题库到学习／交易的后端流程；实际甲方联调仍需交付前端地址、合法域名和真实账号配置，分别在Android／iOS验证登录、试学、激活码、支付成功／取消／退款、跨设备冲突和失权。需提供问题复现步骤、脱敏响应及X-Request-ID，不发秘密值。生产与平台审核完成后由主agent单独记录正式验收，不能用测试外部mock结果代替。
