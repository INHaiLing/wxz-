# P03：微信学员身份与会话

**Author:** P03 开发 agent；评审：主 agent／独立开发 agent。

**Date:** 2026-10-02

**Status:** Approved（用户已批准阶段计划和共享契约）；实现及本机自动化验收完成，真实 PostgreSQL／微信联调另行记录。

## Context（背景）

后台账号和原 `/api/v1/` Session 接口保留。甲方前端调用微信登录取得短期 code，后端通过配置的小程序身份换取微信身份，建立独立学员 Bearer 会话。

模块只建立身份和会话，不发放权益。微信 session_key 后续供官方虚拟支付签名使用，只在服务端加密保存。

## Functional Requirements（功能要求）

- FR-1: MUST `(appid, openid)` 唯一；同微信身份并发登录只创建一个用户，无遗留孤立用户。新用户密码不可用、无后台权限。
- FR-2: MUST 使用 32 字节安全随机 Bearer token，数据库只保存 SHA-256 摘要；会话有效期 7 天，过期、撤销、用户停用或后台账号身份均拒绝。
- FR-3: MUST 后台 Cookie 不能替代学员 Bearer；非法 Authorization 在公开学员接口也返回 401，不能降级匿名。
- FR-4: MUST 登录只接收 code，不信任客户端 appid、openid、session_key；仅访问固定官方 code2session 地址。缺少配置返回 503，无效 code 返回 401，外部失败不泄露请求 URL、响应或密钥。
- FR-5: MUST session_key 用独立 Fernet 密钥加密，第一配置项负责加密、历史项兼容解密；提供批量重新加密命令，数据库及管理页面不展示明文。
- FR-6: MUST 退出撤销当前会话，204；用户停用后现有会话立即不可用。退出后重复使用旧 token 返回 401，客户端可清理登录状态；登录和退出不使用业务 Idempotency-Key。
- FR-7: MUST 登录按可信客户端 IP 数据库限频，默认每分钟 30 次；计数在外部请求和身份事务前提交，失败不能回滚次数。

## Non-Functional Requirements（非功能要求）

- NFR-1 MUST 外部请求默认 5 秒、最多 10 秒，响应最多 64 KiB；不跟随跳转，不在源码、异常提示、审计和日志保存原 token、登录 code 或微信密钥。
- NFR-2 MUST SQLite 回归与迁移一致性通过；PostgreSQL 独立连接验证唯一身份和无孤立用户。后台权限与 CSRF 继续生效。
- NFR-3 MUST 正式账号配置缺失时仍可启动题库后台，学员登录明确不可用；测试替身只在测试中注入，无运行时假登录开关。

## Acceptance Criteria（验收标准）

### AC-1: (FR-1, FR-2, NFR-2)

Given 同一微信身份，When 重复或并发登录，Then 用户和身份各一条、会话可多条，数据库没有明文 token。

### AC-2: (FR-2, FR-3, FR-6)

Given 正常、过期、撤销、停用或后台用户会话，When 访问学员接口，Then 仅正常学员成功；后台 Cookie 无效，非法 token 在公开接口同样 401。

### AC-3: (FR-4, FR-7, NFR-1, NFR-3)

Given 缺失配置、无效 code、超时、超大或不完整响应，When 登录，Then 返回约定错误、无用户和会话写入，失败限频计数保留，不泄露外部信息。

### AC-4: (FR-5)

Given 旧加密密钥，When 新密钥放在首位并运行轮换，Then 会话密钥仍正确、存储密文变化，新主密钥可独立解密；缺失旧密钥时明确失败且整批不部分更新。

## Edge Cases（边界情况）

- EC-1: 微信重复 code、失效 code 或其他认证失败返回 401；接口超时、限流和未知平台错误返回 503，前端获取新 code 后重试。
- EC-2: 非法或缺失加密密钥不使用 Django SECRET_KEY 代替，登录返回 503，不写入明文或孤立账号。
- EC-3: 退出只撤销当前设备会话；后台停用用户撤销所有现存学员会话，重新启用后需重新登录。
- EC-4: 轮换期间新登录遵循 user→identity 锁顺序；每批事务处理，失败批次回滚，已成功的前批可重新运行。
- EC-5: 学员接口不接受后台 Session，已有管理员即使人为关联微信身份也不能用学员会话绕过授权。

## API Contracts（接口契约）

`POST /api/student/v1/auth/wechat/`，仅 JSON `{code:string}`，返回：

```typescript
interface LoginResponse { token: string; expiresAt: string; user: { id: number } }
interface BusinessError { error: { code: string; message: string; fields?: object }; requestId: string }
```

`POST /api/student/v1/auth/logout/`，Bearer 必填，成功 204。登录不需要事先登录，但提供非法 Authorization 仍然 401。所有学员视图只用 `StudentBearerAuthentication`。

前端重新登录时不要发送旧 Authorization；成功收到 token 后替换本机凭证。旧 wx.login code 不重放，网络失败时重新取得 code。调用退出后，无论 204 或旧凭证已失效的 401，都清理本机登录状态。

| HTTP | code | 场景 |
| --- | --- | --- |
| 400 | VALIDATION_ERROR | 非法输入、额外身份字段 |
| 401 | INVALID_TOKEN／WECHAT_CODE_INVALID | 学员凭证或微信登录 code 不可用 |
| 403 | STUDENT_DISABLED | 已认证微信身份对应账号停用或具有后台身份 |
| 429 | RATE_LIMITED | 登录次数达到上限 |
| 503 | WECHAT_UNAVAILABLE／STUDENT_CONFIGURATION_ERROR | 外部能力或安全配置不可用 |

## Data Models（数据模型）

| 实体 | 字段 | 约束 |
| --- | --- | --- |
| WeChatIdentity | user、app_id、openid、encrypted_session_key、created_at、updated_at | app_id+openid 唯一；用户 PROTECT；最新身份密钥明文不得入库 |
| StudentSession | user、token_digest、encrypted_session_key、created_at、expires_at、revoked_at | 摘要唯一；用户 PROTECT；保存本次登录密钥，服务发放后 7 天有效 |

- OS-1: 不增加前端、短信／密码学员登录、身份转移、权益或支付。
- OS-2: 不改根路由、根配置、依赖、总文档；主 agent 合入注册，模块测试通过独立测试 URL。

## 配置与操作

主 agent 注册 `WECHAT_APP_ID`、`WECHAT_APP_SECRET`、`STUDENT_SESSION_ENCRYPTION_KEYS`（有序列表／元组，第一项为主密钥）。默认 `WECHAT_LOGIN_TIMEOUT_SECONDS=5`、`WECHAT_LOGIN_RATE_LIMIT=30`。

支付签名应使用 `decrypt_wechat_session_key(request.auth)` 读取当前 Bearer 对应的微信会话密钥，不能改用另一设备最新登录的密钥。7 天后端会话有效不代表微信 session_key 仍有效；前端购买前需要 `wx.checkSession`，必要时重新调用 `wx.login` 并换取新后端会话。

创建 Fernet 密钥：`python -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"`；仅写入本机／服务器安全配置，勿复制到仓库、聊天或交接材料。轮换先加入新主密钥并保留旧密钥，运行 `python manage.py rotate_wechat_session_keys --batch-size 100`；备份和全部密文迁移验证完成后再移除旧密钥。

微信接入参考：[官方 code2Session](https://developers.weixin.qq.com/miniprogram/dev/api-backend/open-api/login/auth.code2Session.html)。真实登录仍需甲方安全配置和前端 wx.login code，本模块自动化测试不等同真实微信联调。
