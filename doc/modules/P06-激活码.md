# P06：永久激活码与一次领取

**Author:** 开发 agent P06；评审：主 agent／交叉开发 agent。

**Date:** 2026-10-02

**Status:** 已实现，本机及真实 PostgreSQL CI 通过；模块 PR 已提交，待交叉评审及阶段合并。

## Context（背景）

甲方在线下独立收款，后台发放激活码，学员小程序只兑换。激活码没有自然到期，一码一人一次，成功后永久开通全语文题库。

批次原码只能下载一次；服务端保留摘要和掩码。下载失败时必须作废未领取批次再重新生成，不通过重复导出找回原码。

## Functional Requirements（功能要求）

- FR-1: MUST 每码使用 32 字节随机熵，Base32 表示、QM 前缀和四字符分组；允许手输时忽略大小写、空格和连字符，拒绝其他字符及错误长度。
- FR-2: MUST 批次创建时只在内存和首次 HTTP CSV 响应提供原码，不保存到数据库、日志或临时文件；数据库仅存 SHA-256 摘要及少量掩码。
- FR-3: MUST 管理员创建采用幂等键，同键同参数返回已有批次，不重新提供原码；同键不同参数 409。
- FR-4: MUST awaiting_receipt 批次先确认领取变 received，再启用为 enabled；下载失败可作废 awaiting_receipt 批次；enabled 可禁用、disabled 可重新启用，void 永不可恢复。
- FR-5: MUST 批次生成、领取确认、启用、禁用、作废以及单码禁用均校验有效后台账户、独立权限、CSRF；状态操作签名绑定操作者、操作、状态和影响，30 分钟有效并锁内复核；禁用、作废须填写 1～500 字理由并审计。
- FR-6: MUST 批次、码、兑换记录只通过服务写入，后台不能常规新增、编辑或删除；已兑码不能改回未使用，历史始终保留。
- FR-7: MUST `POST /api/student/v1/activation/redeem/` 使用 Bearer、仅接收 code 和 Idempotency-Key；返回 redemptionId、redeemedAt 及当前 entitlement。
- FR-8: MUST 兑换事务按 User→reservation→batch→code→source 加锁；已有权益返回 409 ALREADY_ACTIVATED“已激活”，支付处理中返回 409 PURCHASE_IN_PROGRESS，不消耗新码。
- FR-9: MUST 成功请求原键重放仅返回历史兑换及当前权益，不重复发放；原来源被撤销后重放不恢复；同键不同码 409。
- FR-10: MUST 无效、未领取、未启用、禁用、作废及已兑码拒绝兑换；任何失败整笔回滚，不留下部分使用、来源、兑换或幂等记录。
- FR-11: MUST 用户和可信客户端 IP 限频在业务事务前独立提交，失败请求也计数；响应不暴露原码或其他用户信息。
- FR-12: MUST 已兑误发撤权链接到 P04 的签名影响预览及理由确认；撤销仅影响该来源，码仍已使用，不重新兑换。

## Non-Functional Requirements（非功能要求）

- NFR-1 MUST 批次数量 1～500，CSV 只在内存构建，下载响应 no-store；不依赖额外表格组件。
- NFR-2 MUST 数据库约束摘要唯一、单码单次兑换、单来源单次关联；PostgreSQL 独立连接测试真实竞争。
- NFR-3 MUST 原码不进入幂等记录、审计或异常信息；审计记录批次/码/兑换 ID、操作者、原因和时间。

## Acceptance Criteria（验收标准）

### AC-1: (FR-1, FR-2, FR-3, FR-4, NFR-1, NFR-3)

Given 后台创建批次，When 首次下载、重复提交和领取启用，Then 首次 CSV 含原码，重复不导出，数据库/审计没有原码；未领取不能兑换，失文件作废后新建。

### AC-2: (FR-5, FR-6, FR-12)

Given 缺权限/CSRF/签名或预览后状态变更，When 后台操作，Then 拒绝且整批不生效；已兑来源可经 P04 撤销但码仍已使用，后台无直接编辑/删除入口。

### AC-3: (FR-7, FR-8, FR-9, FR-10, NFR-2, NFR-3)

Given 可用码、已激活或占位账号及旧成功请求，When 兑换或重放，Then 一次成功，新码不被重复开通消费，撤权重放不恢复，失败无部分记录。

### AC-4: (FR-8, FR-9, FR-10, NFR-2)

Given PostgreSQL 独立连接同码多人、同人多码或支付占位与兑换竞争，When 提交，Then 只一次开通，不超兑；撤权后旧幂等请求不能再发放。

### AC-5: (FR-7, FR-11)

Given 后台 Cookie、非法 Bearer、附加字段、缺幂等键和连续错误兑换，When 请求 API，Then 认证/输入拒绝并累计限频，错误不泄露原码或其他账户。

## Edge Cases（边界情况）

- EC-1: 首次下载断开、事务后进程终止或文件遗失，批次保持待领取但不能重新下载；作废后生成新批次。
- EC-2: 确认领取后遗失文件，禁用批次未兑码并创建新批次；历史已兑权益不受批次禁用影响。
- EC-3: 批次禁用与兑换竞争通过批次锁裁定；禁用完成后不能兑换，先完成的兑换仍保留权益。
- EC-4: 兑换成功响应丢失，原键原码重放返回同 redemptionId；不同键再次开通提示已激活，不重复消费。
- EC-5: 撤销全部来源后可用新码重新开通，旧码仍已使用；旧成功重放返回当前未激活。
- EC-6: 原码摘要重复极低概率仍由数据库唯一约束拒绝，整批创建失败而非覆盖旧码。

## API Contracts（接口契约）

`POST /api/student/v1/activation/redeem/`；后台 `POST /admin/activation/activationbatch/generate/` 和签名状态操作。

```typescript
interface RedeemInput { code: string }
interface RedeemResult { redemptionId: string; redeemedAt: string; entitlement: { scope: "all_chinese"; active: boolean; permanent: boolean; expiresAt: null } }
interface BusinessError { error: { code: string; message: string }; requestId: string }
interface GenerateInput { quantity: number; label?: string; idempotencyKey: string }
```

成功 200；输入 400、认证 401、权限 403、业务/幂等/状态冲突 409、限频 429。普通错误不回显 code。内部 generate_batch 返回批次及仅首调用的内存原码；兑换幂等记录只保存码摘要载荷和历史兑换 ID/时间，不保存原码或过时权益快照。

## Data Models（数据模型）

| 实体 | 字段 | 约束 |
| --- | --- | --- |
| ActivationBatch | UUID、数量、说明、状态、version、创建者/领取者、时间 | 状态服务转换、数量 1～500、永不过期 |
| ActivationCode | UUID、batch、digest、mask、state、redeemed_by/at、disabled_at/reason | digest 唯一、使用状态不可恢复、无原码列 |
| ActivationRedemption | UUID、code、user、source、redeemed_at | code/source 一对一、外键 PROTECT、历史保留 |
| IdempotencyRecord/AuditEvent | 复用公共和权益层 | 摘要及历史结果、操作者和业务 ID |

## Out of Scope（本模块之外）

- OS-1: 不收线下款、不展示购买联系方式/二维码、不实现支付；没有机构标签或激活码期限。
- OS-2: 不开发前端、不修改根配置/路由/依赖/全局文档；主 agent 整合注册。
- OS-3: 不提供原码找回、重新导出或已兑码复用；未创建的真实题库与支付环境不作验收完成声明。

## 操作与验收记录

后台批次列表“生成并一次下载 CSV”→保存 CSV→批次详情“确认文件已领取”→“启用批次”。若首次文件未保存，填写理由作废待领取批次后使用新的生成请求创建批次；系统无法再次显示原码。同一生成请求重复提交只跳转已有批次。

批次禁用保留已兑权益，重新启用仅恢复仍未使用、未单码禁用的码；单码禁用不会因批次重新启用而恢复。已兑码详情“查看对应权益及误发撤权”进入 P04 只读来源页面，再预览影响、填写理由并签名确认；码仍已使用。

后台角色需分配 `view_activationbatch/view_activationcode/view_activationredemption` 及对应受控操作权限：`generate/receive/enable/disable/void_activationbatch`、`disable_activationcode`。误发撤权另需 P04 的 `view_entitlementsource/revoke_entitlementsource`。即使拥有普通 change/add/delete 权限，也不能直接覆盖业务记录。

后台确认签名失效、状态或影响变化返回 409；错误页没有新的确认凭证，需要重新打开预览。生成 API 幂等键由表单自动生成；学员前端自行提供 8～128 位 `Idempotency-Key` 并保存成功兑换的原键以重试。同一原码大小写或分隔符不同仍视作相同载荷。

兑换限频默认每学员每分钟 10 次、每可信客户端 IP 每分钟至少 30 次，在业务事务前独立提交；格式错误、不可用码和回滚事务均计入。总配额由 `ACTIVATION_REDEEM_RATE_LIMIT` 控制，生产代理信任仍按公共 `TRUSTED_PROXY_IPS` 配置，不接受随意传入的转发头。
