# P09 订单与支付准备

状态：已实现、已测试、已完成交叉审核；[模块 PR #15](https://github.com/INHaiLing/wxz-/pull/15)。线上虚拟支付，无扫码；真实渠道未开通不能发起支付。

## 1. 背景

全题库永久权益单商品；成交金额快照和微信客户端参数由服务端生成，客户端成功不直接发权。

## 2. Functional Requirements

- FR-1 MUST 新订单核对账户、商品、渠道及已有永久权益；幂等重试不新增订单。
- FR-2 MUST 订单保存商品名称、范围、分金额、平台商品、appid、环境和设备渠道快照。
- FR-3 MUST 创建本地订单不占位；签名参数出站前事务内占位并写持久查询任务。
- FR-4 MUST 官方签名使用 exact signData、环境 AppKey 与当前 Bearer 对应的加密微信 session_key；不输出密钥。
- FR-5 MUST 本人查询分页及详情，后台只读；关闭／退款／发权由 P10 服务端状态机负责。

## 3. Non-functional Requirements

所有交易 User 行锁与事务；参数严格 JSON，幂等成功只存安全结果；令牌及签名不记录到日志。业务 ID 为 UUID hex（32 字符），不信任客户端价格、appid或付款状态。

## 4. Acceptance Criteria

- AC-1 Given 已激活用户，When 新建订单或请求支付，Then 409 已激活，不新增或消费码。
- AC-2 Given 商品改价或关闭渠道，When 准备旧订单，Then 拒绝，不发签名或占位。
- AC-3 Given 并发兑换与付款准备，When 获取同一 User 锁，Then 只有一个新开通路径；参数未出站失败整批回滚。
- AC-4 Given 两设备微信密钥不同，When 当前设备准备，Then 使用当前会话签名，不使用最新身份密钥。
- AC-5 Given 已准备订单，When 重试或本地取消，Then 保持原订单和占位；不自行关闭。终态重试不再输出可支付包。

## 5. Edge Cases

未知商品／外人订单、无效JSON、重复参数、未知字段、签名配置缺失、停用账号、过期会话、平台映射未同步、同键异参均明确拒绝。P10 最终未付款确认之前不释放，已付款开通冲突由人工核查。

## 6. HTTP 契约

统一 `/api/student/v1/`：`POST orders/` 输入 `{productId,channel}`；`GET orders/`、`GET orders/{id}/`；`POST orders/{id}/payment/` 输入 `{}`。POST需 `Idempotency-Key`。支付响应 `{order,payment:{mode,signData,paySig,signature}|null,entitlement}`，signData 为字符串，原样传 `wx.requestVirtualPayment`，不可重序列化。查询／发货／退款入口由 P10 提供。

## 7. 模型与内部约定

Order 主键32位hex，本人／身份／商品引用和成交快照；状态 created/preparing/paid/fulfilled/closed/refunded/review。`PaymentTask` 每 order+kind(query/deliver) 唯一，租约／重试／next_run_at 支持 P10；准备事务安排查询任务。所有模型只服务写、不可直接改删。来源 payment/sourceId=本地订单ID。

- [x] 严格参数、幂等／权益／配置／跨设备签名；PG 专属竞争用例已提交，以实际 CI 结果为准

## 9. 依据与待联调

签名、字段和协议核对 [官方虚拟支付](https://developers.weixin.qq.com/miniprogram/dev/platform-capabilities/business-capabilities/virtual-payment.html) 与 [requestVirtualPayment](https://developers.weixin.qq.com/miniprogram/dev/api/payment/wx.requestVirtualPayment.html)。客户端支付成功后查询后端，不把 success 回调当成权益证明；真实 Android/iOS 验收单列。

## 10. 整合中的账户权限加固

后台“学员账号启停”使用只读代理模型及独立 `accounts.set_student_status` 权限，业务操作人员不获得可修改管理员身份、权限组的 `accounts.change_user` 权限。启停需要签名影响预览、确认、1～500 字理由和 CSRF；预览与操作者、学员、动作及状态指纹绑定，过期或冲突返回 409。不可删审计记录形成单调状态版本，即使停用后再次启用，旧确认单也不能重放。停用立即注销全部学员会话，启用后需要重新微信登录；管理员及未关联微信的账号不能通过此入口修改。7 项测试覆盖权限隔离、状态冲突、字段注入、理由和 CSRF。

支付准备的成功与错误响应均禁止缓存；同键重试重新核对渠道、配置指纹、商品快照及本次设备微信身份，不允许绕过后续禁售或配置变化。配置密钥只参与指纹与签名，不写入订单或响应。

实际 [CI](https://github.com/INHaiLing/wxz-/actions/runs/36980285403)：PostgreSQL 16 的 249 项全部通过，Windows／Linux SQLite 和历史前端均通过。包含签名向量、双设备、配置重试、兑换与支付准备竞争、旧确认单状态循环重放等验证；迁移漂移及空库初始化检查通过。真实微信渠道未验收。

## 11. Apple 支付上线门槛修复规格

依据 2026-10-02 重新核对的[微信官方虚拟支付说明](https://developers.weixin.qq.com/miniprogram/dev/platform-capabilities/business-capabilities/virtual-payment.html)：Apple 支付不支持沙箱，只支持现网；最低支付金额为 1 元。Android 原有环境及正整数分价格规则继续保留。iOS 开关默认关闭。

- FR-6 MUST iOS 渠道在 `VIRTUAL_PAYMENT_ENV=1` 或商品价格低于 100 分时不可购买；商品接口的 `paymentChannels.ios` 为 false。
- FR-7 MUST 新建订单、准备支付及可再次输出支付参数的幂等重试重新检查 iOS 环境与金额；拒绝使用现有 `PAYMENT_CHANNEL_UNAVAILABLE`、HTTP 503，不创建订单、占位、任务或成功幂等记录。
- FR-8 MUST 创建订单的原成功幂等重试只返回历史订单及当前权益；准备支付的终态重放只返回历史和当前权益，不输出支付参数。历史读取、可信查单和退款同步不受新销售门槛影响，不因关闭 iOS 开关而丢失已发生的交易。
- AC-6 Given iOS 沙箱或 99 分已同步商品，When 新建订单或准备/重试支付，Then 拒绝且所有交易状态保持不变；商品接口 iOS 为 false。
- AC-7 Given iOS 现网 100 分已同步商品，When 创建并准备支付，Then 输出原有签名契约且只安排一个查询任务；同样的 Android 沙箱低价商品仍可用。

客户端还须验证 iOS 15 及以上、微信 8.0.68 及以上与中国大陆 App Store 账号条件；服务端无法从客户端自行上报的系统版本证明 Apple 资格。两项后端门槛通过自动化验证也不能代替真实渠道及设备验收。

修复验证：新增 8 项实际商品／交易／幂等与可信状态同步测试，定向 25 项通过；完整本机 SQLite 回归 323 项，其中 290 项通过、33 项真实 PostgreSQL 专属并发用例按设计跳过。迁移漂移检查与 `git diff --check` 通过。真实 PostgreSQL CI 及交叉审核结果见[修复 PR #19](https://github.com/INHaiLing/wxz-/pull/19)，不将本机跳过项记为已通过；真实 Apple 设备仍待验收。
