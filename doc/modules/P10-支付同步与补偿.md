# P10：支付同步、退款与持久补偿

**Author:** P10 开发 agent；主 agent 交叉审核。

**Date:** 2026-10-02

**Status:** 阶段计划已批准，规格冻结，实施中；真实渠道待甲方环境联调。

## Context（背景）

P09 已生成本地成交快照、官方支付签名和开通占位。客户端支付成功不能代表发权；本模块通过微信安全消息及服务端查单确认付款，统一事务发放全题库永久权益，完成发货、退款同步和可靠补偿。

## Functional Requirements（功能要求）

- FR-1: MUST GET 接入验证支持官方 signature(Token,timestamp,nonce) 与加密 echostr；POST 业务仅接受安全模式 msg_signature(Token,timestamp,nonce,Encrypt) SHA1 验签及 AES-CBC 解密，严格验证 32 字节 PKCS7、网络序消息长度与 appid。
- FR-2: MUST 原始 JSON/XML 限大小、拒绝重复字段、DTD/实体、非法结构；校验订单、身份 OpenId、appid、Env、商品、数量、成交价和 attach，签名或金额错误不发权。
- FR-3: MUST 发货通知和查单复用 User→reservation→Order→source 锁序及统一状态机；重复/并发只发一次，DB 提交成功后才确认微信消息。关闭、退款和撤权不会被迟到付款恢复。
- FR-4: MUST 查单状态 2/3/4 发权并安排发货补偿；0/1/未知不释放占位，仅 6 最终未付款关闭可释放。已付款与其他有效来源冲突记录 review，不吞款或自动退款。
- FR-5: MUST 成功退款事件仅撤对应 payment 来源并保留历史；退款可早于付款，RetCode 非 0 不撤权；可信查询 5/8 仅全額最终退款撤权，7 退款失败不撤权，部分/不确定金额进入核查。
- FR-6: MUST 平台订单号/交易号禁止跨订单复用；事件以可信稳定摘要幂等，原始消息、密钥、访问令牌及客户端签名不进入日志或业务审计。
- FR-7: MUST 仅通过固定 HTTPS 官方端点获取和加密缓存 access_token、exact JSON body HMAC 查询现金订单，以及无 pay_sig 的通知发货接口；拒绝重定向、超时、超大或畸形响应，不伪造运行成功。
- FR-8: MUST `POST /api/student/v1/orders/{id}/query/` 仅本人、Bearer、空 JSON 和 Idempotency-Key；限频先提交，成功重放返回当前状态，不重发权益。
- FR-9: MUST 持久任务短事务领取租约后释放 task 锁，再获取 User；有界指数重试、过期接管、租约 token 对比防旧 worker 覆盖，耗尽标记 failed 需核查。
- FR-10: MUST 后台订单/事件/任务只读；失败任务重调度要求独立权限、理由、CSRF、30 分钟签名影响预览，不能直接改为已付或发权。
- FR-11: MUST iOS 退款问询保留事件但不擅自给建议 0/1，通过非成功响应进入官方“不确定”路径；实际完成退款事件正常同步。

## Non-Functional Requirements（非功能要求）

- NFR-1 MUST PostgreSQL 独立连接验证通知/查单/退款竞争与多 worker 租约；SQLite 只验证普通流程，明确跳过交易竞争。
- NFR-2 MUST 网络调用不持 User 或 Order 事务锁；超时 5 秒、响应 64 KiB，消息 64 KiB，未知错误不能回 success。
- NFR-3 MUST 永久来源 expires_at null，审计来自可信系统事件不伪装管理员；真实 Android/iOS 渠道验收单独记录。

## Acceptance Criteria（验收标准）

### AC-1: (FR-1, FR-2, FR-6, NFR-2)

Given 官方签名加解密向量及伪造/重复/未知订单/金额错误，When HTTP 消息推送，Then 只有严格有效的支付消息进入状态机，拒绝不会发权或返回成功。

### AC-2: (FR-3, FR-4, FR-5, FR-6, NFR-1, NFR-3)

Given 同一订单重复付款、退款先到、迟到关闭和其他来源，When 消息与查单竞争，Then 发权最多一次，退款/撤权不恢复，只有最终未付关闭释放占位，其他来源仍有效。

### AC-3: (FR-7, FR-8, NFR-2)

Given 真实身份和服务端配置，When 本人查询及固定官方 HTTP 调用，Then 签名与出站包体一致、令牌加密缓存，Cookie/外人/缺幂等/限频均拒绝，异常不冒充成功。

### AC-4: (FR-9, FR-10, NFR-1)

Given 多 worker、失联租约、重试耗尽及管理员，When 补偿和重调度，Then 同租约只一个有效处理者，旧 worker 不能覆盖，后台权限/CSRF/签名/理由均必需。

### AC-5: (FR-11, FR-5)

Given iOS 退款问询和后续完成退款，When 安全事件到达，Then 问询不产生业务建议或权益变更，完成退款仍可撤对应来源。

## Edge Cases（边界情况）

- EC-1: 网络已成功、worker 在更新租约前终止：下次接管重复查单/发货，共享幂等不重复发权。
- EC-2: 成功发权后消息响应丢失：平台重推同事件可再次确认，但不会重复来源/审计。
- EC-3: prepared 占位不能因客户端取消、未发现平台订单、0/1 或网络超时释放；查单耗尽等待核查。
- EC-4: 退款消息不含 Env，根据本地订单环境、加密 appid 和 OpenId 校核；可信查单最终退款使用查询快照摘要标记审计来源，不捏造微信退款号。
- EC-5: 非全额退款、金额缺失和订单号冲突记录核查，不自动撤所有永久权益；管理员不能手工伪造已付或退款成功。
- EC-6: 渠道关闭后已存在订单同步仍需要有效服务端 appid/环境密钥；新付款准备继续拒绝，历史交易不能因售卖总开关关闭而失去退款同步。

## API Contracts（接口契约）

```typescript
interface QueryInput {}
interface QueryResult { order: {id:string; status:string; priceFen:number}; entitlement:{scope:"all_chinese";active:boolean;permanent:boolean;expiresAt:null} }
interface ErrorResult { error:{code:string;message:string};requestId:string }
```

学员 `POST orders/{id}/query/` 需 8～128 位 Idempotency-Key，200 或标准 400/401/404/409/429/503；后台签名状态冲突 409。`GET/POST /integrations/wechat/virtual-payment/` 为微信回调；成功 `success` 等价官方 ErrCode=0，无需加密响应；失败非 2xx 或官方非零错误，不虚报发货。iOS 退款问询返回非成功，交由官方不确定流程。

## Data Models（数据模型）

Order/PaymentTask 复用 P09，补平台 ID 非空唯一约束与任务权限。PaymentEvent 保存可信事件摘要、事件类型、订单、结果、核查代码和脱敏字段，无原始消息。AccessTokenCache 保存 appid、加密令牌和过期时间。任务状态 pending/running/done/failed，attempts、lease_token/lease_until、next_run_at 与 last_error_code。

| 实体 | 主要字段 | 约束 |
| --- | --- | --- |
| Order | 平台订单号、交易号、成交快照 | 非空全局唯一、仅服务写入 |
| PaymentTask | order/kind、租约、attempts、next_run_at | 每订单类型唯一、有效租约才可完成 |
| PaymentEvent | key、order、request_digest、kind、outcome | 稳定摘要幂等、无原始消息、不可删除 |
| AccessTokenCache | appid、ciphertext、expires_at | appid 唯一、加密令牌、服务端专用 |

## Out of Scope（范围边界）

- OS-1: 不发起退款、不决定 Apple 退款问询、不接普通微信支付 v3、不收线下款。
- OS-2: 不开发甲方前端、真实支付环境或公网部署；主 agent 负责根配置、路由和生产调度示例。
- OS-3: 不依赖内存队列或假付款；真实渠道完成前不声明上线验收。
