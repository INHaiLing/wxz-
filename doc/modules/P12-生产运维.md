# P12 生产配置与恢复

状态：代码已实现，自动化验证通过，PR #10 待阶段合并；生产环境尚未提供，不能据本模块测试声称上线。

## 1. 背景与范围

为模块化 Django 后端提供 Linux + PostgreSQL 16 + HTTPS 部署模板、可验证备份恢复、启动检查和脱敏日志。Windows SQLite 继续用于开发。

## 2. Functional Requirements

- FR-1 MUST 生产禁用 DEBUG、使用 PostgreSQL、明确 Host/CSRF/HTTPS，缺少必要秘密配置时启动失败。
- FR-2 MUST SQLite 使用在线快照，PostgreSQL 使用原生 custom dump；备份文件独占创建并限制权限。
- FR-3 MUST 恢复到独立目标，不能覆盖当前配置库／已有文件；恢复后核对完整性与迁移。
- FR-4 MUST 就绪检查验证数据库但不返回连接信息；HTTP 日志仅包含请求标识、路由、耗时及状态。
- FR-5 MUST 运维可重复初始化权限／商品，补偿定时任务与业务部署分离；正式数据迁移和回退有说明。
- FR-6 MUST 在真实 PostgreSQL 16 对一次性 SQLite 数据做 migrate→seed→快照→受控 dumpdata→新 PG 库 migrate／loaddata 演练；核对全部业务载荷、稳定题目 ID／发布修订、学员与权限组、有效永久来源和撤销审计，原库不变。只清理脚本亲自创建且符合随机命名的目标，不能指向当前配置库。
- FR-7 MUST 创建缺失的业务查看、学员启停、商品运营、激活码管理、权益撤销、支付核查六个分离权限组。所有权限按实际 app／model／codename 完整验证，缺失整批失败；已有组权限保留，不自动扩大，不创建账户／密码或把用户加入组。学员启停只授专用 proxy 权限，绝不授 change_user。

## 3. Non-functional Requirements

备份及外部进程有限时、参数数组调用，无 shell 插值或密码参数；日志不记录请求体、查询、头、令牌、码或密钥。未提供服务器、域名、渠道，不创建公网服务。

## 4. Acceptance Criteria

- AC-1 Given 不合规生产配置，When 启动，Then 明确拒绝。
- AC-2 Given 含题库及业务数据的独立库，When 备份后恢复到空目标，Then 数据一致、原库不变。
- AC-3 Given 数据库异常，When GET readyz，Then 503 且不泄露配置；正常返回 200。
- AC-4 Given 含敏感请求，When 记录日志，Then 输出不包含输入秘密；POST 体与 query 不出现。
- AC-5 Given 全新环境，When 按运维手册初始化，Then 完成迁移、角色及商品初始化，生产检查通过。
- AC-6 Given 脚本生成的 SQLite 测试学员、两版发布内容和有效／撤销永久来源，When 实际迁移到随机新 PostgreSQL 库，Then 业务载荷与加密会话可验证一致、目标约束有效、SQLite 源及快照不变；清理仅处理自己创建的库，不声称生产数据已迁移。
- AC-7 Given 自定义已有组或缺失权限，When 重复 setup_business_roles，Then 自定义权限保持原样、缺权限不创建部分组；激活码管理不能撤权，权益撤销不能发码／改价，学员启停不能修改账户权限。

## 5. Edge Cases

已有目标、损坏 SQLite、错误 pg_dump 版本、恢复工具缺失、非空目标库、失败进程与超时均拒绝或保留原状，不静默覆盖。备份恢复后必须恢复匹配加密密钥，不能自动生成新密钥冒充恢复成功。

## 6. 接口与命令

`GET /readyz` 仅状态；保留 `/healthz`。`backup_database --output PATH`；`restore_database --input PATH --target PATH_OR_DATABASE`，恢复离线独立目标后再切换应用配置。`setup_business_roles` 只创建缺失业务组，实际模型声明与数据库权限双重核验，保留已有组权限。部署模板中的域名与路径需运营方填写。

`scripts/verify_database_transfer.py` 使用显式 TEST_DB_*，创建临时 SQLite 源与随机 PostgreSQL 16 目标，不接受生产目标参数。私有自然外键导出后核对完整载荷、约束与源文件哈希；清理仅针对本次亲自创建的目标。

支付补偿模板以 oneshot 服务执行 `run_payment_tasks --limit 50`，退出一分钟后再运行，600 秒超时并防止同一服务重入；每小时 `schedule_payment_reconciliation --limit 1000 --older-than-hours 24`。失败任务不自动重置，支付核查人员先核查，再预览、填写理由并确认重新调度；不直接发权益。

## 7. 模型与依赖
