## 1. 元信息

日期2026-10-02；状态已实现、本机回归通过，真实PostgreSQL CI及最终交叉审核待根agent整合。范围依据已批准P10可靠支付、异常补偿与退款核查要求，及用户要求把全部后端落实的授权。本轮在本机验证，不发起实际付款或公网部署。根agent整合，支付agent实现，配置／文档agent交叉审核。

## Context（2. 背景）

已实现支付主流程及323项真实PostgreSQL16回归。进一步核查发现：缓存中的平台令牌被其他客户端提前作废后，目前会持续重用到本地到期；Apple问询仅记录uncertain而缺少安全关联，首次同消息并发写入可能主键冲突；已耗尽任务可能使后续正常到期任务多等一轮调度。

本模块落实原有支付可靠性和人工核查职责，不扩展商品、退款决策或付款接口。原永久来源与占位规则继续有效。

## Functional Requirements（3. 功能要求）

- FR-1: MUST 只在固定xpay查单／发货返回确定令牌无效或过期数字码40001／40014／42001时，比较失效本次使用的旧缓存，使用stable_token force_refresh=false重新取当前令牌并最多重试原请求一次。
- FR-2: MUST 并发旧请求不能清空另一个请求刚刷新的有效缓存；令牌刷新继续应用加密存储和缓存行锁，网络／非令牌业务错误不强刷、不无限重试、不伪装平台成功。
- FR-3: MUST 平台数字错误仅作为内部控制信号；原公开BusinessError继续安全PLATFORM_UNAVAILABLE，不暴露errmsg、URL、正文、签名或令牌。原精确body/pay_sig在重试时保持一致。
- FR-4: MUST 接受官方stable_token有效但剩余不足120秒的正整数expires_in（上限7200），采用提前到期策略；无效或零期限仍拒绝。
- FR-5: MUST Apple问询仅保存已校验、限长的核查元信息，保守关联已知同AppID、iOS、商品／数量匹配的本地订单。不凭未知支付编号猜测订单，不保存完整回执或openid，不发权／撤权。
- FR-6: MUST 同一已验签解密问询并发首次到达和重放最多产生一个事件，不导致破坏外层事务的IntegrityError；关联字段异常或无法关联时保存可解释的安全核查状态，不变更订单／权益／占位。
- FR-7: MUST 继续已批准Apple问询的uncertain兜底：HTTP503交由官方三次未应答机制处理，不编造result_code=2、不自动同意／拒绝退款。实际退款状态机保持原语义。
- FR-8: MUST 标记过期且已耗尽的任务后继续有界查找后续到期任务，保持租约、MAX_ATTEMPTS、skip_locked与旧租约不可提交的规则，不用无界循环占据事务。

## Non-Functional Requirements（4. 非功能要求）

- NFR-1: MUST 每次查单／发货最多两次xpay请求及一次必要stable_token刷新，不加入无限重试或额外睡眠；既有每次HTTP请求5秒超时和64KiB响应上限继续保留。
- NFR-2: MUST 问询元信息只允许官方字段白名单、合理长度／类型；任何外部异常原文不得进入日志或错误响应。数据库仍仅使用既有PaymentEvent／AccessTokenCache／PaymentTask模型。
- NFR-3: MUST 真实PostgreSQL独立连接验证令牌旧缓存竞争与同问询首次竞争；SQLite测试跳过不能作为并发验收。

## Acceptance Criteria（5. 验收条件）

### AC-1:

Given 本地缓存提前失效，When xpay返回令牌错误，Then 比较失效、false刷新、相同请求最多重试一次并正确返回；非令牌错误及重复失效仍安全失败。(FR-1, FR-2, FR-3)
### AC-2:

Given 其他线程已缓存新令牌，When 旧令牌失败触发刷新，Then 保留新缓存，不把新值清空；独立连接结果一致。(FR-2，NFR-3)
### AC-3:

Given stable_token剩余有效时间30秒，When 获取令牌，Then 返回可用令牌并合理安排缓存到期；零／负数／bool／超上限仍拒绝。(FR-4)
### AC-4:

Given 官方Apple问询并重复／并发到达，When 验签后核查，Then 只一个事件、保留安全信息和保守关联；仍503，订单、权益、占位不改变。(FR-5, FR-6, FR-7，NFR-2, FR-3)
### AC-5:

Given 未知订单、商品／数量不匹配或畸形问询字段，When 接收，Then 不错误关联且不发权／撤权，不保存超长或秘密原文。(FR-5, FR-6)
### AC-6:

Given 队首耗尽且后面有正常到期任务，When 本轮worker执行，Then 耗尽任务failed、后续任务仍能处理，租约及次数边界不变。(FR-8)

## Edge Cases（6. 边界与异常）

- EC-1: stable_token自身40001可能是AppSecret错误：不递归刷新，只安全失败。
- EC-2: HTTP超时、重定向、格式错误、限流或其他errcode：使用既有补偿，不进入令牌重试分支。
- EC-3: 再次重试仍令牌失效：停止本次请求，持久任务记录安全失败码。
- EC-4: 已关闭新销售：既有订单仍可核验与退款同步，不能重新开通已撤来源。
- EC-5: Apple支付编号含义未明确：仅已存本地ID或已核验平台ID精确匹配，不猜前缀／其他字段；无法关联仍保留uncertain核查。
- EC-6: 旧版仅有公共问询字段：保留已验证消息的uncertain记录，说明信息不足；未知/缺失信息不作为允许退款的依据。
- EC-7: 耗尽任务很多：扫描有固定上限，记录耗尽并留待后续调度，不无界持锁。

## 10. 实现与验收记录

### 10.1 令牌恢复

`PlatformRequestFailure` 只保留内部数字控制码，公开响应仍是503 `PLATFORM_UNAVAILABLE`，不附平台errmsg或数字码。`xpay_post` 仅支持既有查询／通知发货两个固定端点，40001／40014／42001触发一次比较失效与普通stable_token获取；第二次拒绝或stable_token自身错误直接失败。重试原body和pay_sig完全不变，发货仍不带pay_sig；没有睡眠、递归或force_refresh=true。

缓存行锁内解密比较本次实际使用的旧令牌，只有相同旧值才能失效；已被其他请求更新的缓存保留。正整数有效期1～7200秒均接受，安全余量取 `min(120, expires_in / 2)`，例如30秒令牌缓存15秒，7200秒令牌缓存7080秒。令牌仍Fernet加密保存，未增加模型或迁移。

### 10.2 Apple问询核查

使用官方9个**顶层string字段**，不自造`IosRefundQueryInfo`等包装。

| 官方字段 | 审计处理／上限 |
| --- | --- |
| refund_time、order_time | 15字符ASCII非负整数串 |
| channel_bill | 4096字符以内，仅保存SHA256为`channel_bill_digest`，不保存完整票据 |
| bundleid | 255字符 |
| product_id、pay_order_id | 128字符 |
| p_count | 9字符ASCII正整数串；关联只允许数量1 |
| refund_request_reason | 256字符 |
| provide_status | 仅字符串0／1／2 |

字段拒绝控制字符和孤立Unicode代理字符；异常字段只记录白名单字段名，不保存原值。未知字段、openid、完整票据均不保存。`details` 结构为 `{policy,info,association,missing_fields,invalid_fields}`；`policy=platform_uncertain`，`info` 为通过校验的白名单值及票据摘要。`external_id` 保存通过校验的支付参考编号，`order` 仅在可靠关联时设置。

`pay_order_id` 只与已存本地Order.id或已核验platform_order_id精确比较；唯一候选还必须同AppID、iOS、平台商品一致、数量1。关联状态为linked／invalid_fields／insufficient_info／unknown_order／ambiguous_order／order_mismatch／product_mismatch／quantity_mismatch；未关联记录对应安全`REFUND_QUERY_*`核查码。只含原公共字段的旧消息继续保存uncertain并说明信息不足。所有情况继续503、不建议退款、不发权／撤权、不改订单／占位。

同一解密消息使用既有稳定摘要幂等；首次并发唯一冲突在内层savepoint回滚后读取已经提交的相同事件，外层事务仍可用。畸形Unicode转义以转义文本计算摘要，仅保存异常字段名；不把畸形字段写入审计。

### 10.3 补偿队列

每次领取最多扫描50条到期候选。耗尽记录标failed并清理旧租约后继续扫描；正常候选仍由skip_locked和随机租约互斥。超过固定扫描上限交由下一次调度；后台人工重调度权限、理由、CSRF、次数及旧租约规则保持不变。
