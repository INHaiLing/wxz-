# P04：商品与永久权益

**Author:** 开发 agent P04；评审：主 agent／交叉开发 agent。

**Date:** 2026-10-02

**Status:** 已批准（阶段计划及共享契约）；实施中。

## Context（背景）

题库已具有后台发布能力。本模块建立激活码与支付共用的权益基础：一个全题库商品、永久来源、可追溯撤销及开通占位。没有任何来源以 365 天或远期日期代替永久。

业务来源不能由后台直接添加或改为付款成功；商品、权益来源和审计以独立模块交付，学员认证由 P03 提供。

## Functional Requirements（功能要求）

- FR-1: MUST 以 `all_chinese` 为唯一范围，初始化 1000 分全题库商品；初始化不覆盖管理员已改价格和配置。
- FR-2: MUST 后台可修改商品价格、启用状态和平台商品映射；改价或映射变化后标记待同步，记录管理员同步确认及操作者。
- FR-3: MUST 来源类型为 activation/payment，类型加业务 ID 唯一；永久来源的 expires_at 必须为空；记录创建、撤销及原因。
- FR-4: MUST 来源发放幂等，撤销后同来源重试不能恢复；来源不能跨用户或范围复用。
- FR-5: MUST grant/revoke/reserve/release/check_new_opening 在事务中先锁现成 User，然后锁占位，再操作来源；新开通已有权益返回 409 ALREADY_ACTIVATED，存在支付占位返回 409 PURCHASE_IN_PROGRESS。
- FR-6: MUST 支付准备使用 user+scope 唯一占位，本地订单创建不占位；同订单 reserve 重试不重复审计；仅调用方核验最终未付款并明确传入 verified_final_unpaid=True 才可释放。
- FR-7: MUST payment 来源 ID 为本地订单 ID；可信内部付款确认发放时消费同订单占位，不能影响其他订单占位。
- FR-8: MUST 撤销需有效后台账户、专用权限和非空理由；管理页面先展示影响并签名绑定操作者、来源和当前范围状态，30 分钟有效，POST 需 CSRF 且锁内重新核验。
- FR-9: MUST 撤销仅影响目标来源，其他有效来源仍提供权限；重复撤销不重复审计，不删除来源或已用码／订单历史。
- FR-10: MUST 权益来源、占位和审计不能经后台直接新增、编辑或删除；审计记录业务变更且不可修改。
- FR-11: MUST `GET /api/student/v1/products/` 匿名可读商品，返回列表、金额分及永久规则；支付总开关、平台开关、商品启用和同步状态均满足才显示可购买。
- FR-12: MUST `GET /api/student/v1/me/entitlements/` 只查询已登录学员本人；Cookie 不能代替 Bearer，非法令牌不能匿名降级。

## Non-Functional Requirements（非功能要求）

- NFR-1 MUST 数据库约束防止重复来源和重复占位；并发用例在 PostgreSQL 16 独立连接执行，SQLite 明确跳过真实行锁测试。
- NFR-2 MUST 审计与接口不保存／返回原码、Bearer、微信密钥；同步标记不代表已经完成真实支付验收。
- NFR-3 MUST 每次权限、影响确认和业务变更同一事务；失败不留下部分权益、占位或审计。

## Acceptance Criteria（验收标准）

### AC-1: (FR-1, FR-2, FR-11)

Given 空库或管理员已改价，When 重复初始化、改价并确认平台同步，Then 仅空库生成 1000 分商品，人工价格保留，状态按规则变化，渠道缺失时不可购买。

### AC-2: (FR-3, FR-4, FR-7, FR-9)

Given 同来源重试、撤销来源重试及另一用户复用来源，When 发放，Then 不重复发放、不恢复撤销来源、不跨用户复用；支付成功消费匹配占位。

### AC-3: (FR-5, FR-6, NFR-1, NFR-3)

Given 两个新开通请求或同来源并发，When 在 PostgreSQL 独立事务执行，Then 用户锁及唯一约束保证一次占位／一次来源，另一请求得到业务冲突，失败不留下部分写入。

### AC-4: (FR-8, FR-9, FR-10, NFR-2, NFR-3)

Given 未授权、缺 CSRF、篡改／过期／跨管理员确认或预览后新增来源，When 撤销，Then 拒绝且无变化；有效确认只撤销目标来源，显示剩余权益影响且审计不可编辑。

### AC-5: (FR-12)

Given 学员 A、B，后台 Cookie、失效 Bearer，When 查询本人权益，Then 仅本人数据可读，后台 Cookie及非法令牌返回 401。

## Edge Cases（边界情况）

- EC-1: 权益为空或用户停用时查询为未激活；永久规则的 expiresAt 始终 null。
- EC-2: release 缺少最终未付款核验、平台暂查不到或仅客户端取消，服务拒绝释放。
- EC-3: 旧订单释放请求不能释放另一个订单的新占位；相同释放成功重试不重复审计。
- EC-4: 支付退款／管理员撤销后只有剩余有效来源决定访问；旧成功发放重试仅返回原来源。
- EC-5: 平台同步确认期间商品改价或映射变更，旧签名拒绝；历史成交由后续订单保存，不在此修改。
- EC-6: 非原子调用 lock_user 为编程错误，不能假装已经持有事务锁。

## API Contracts（接口契约）

`GET /api/student/v1/products/` 和 `GET /api/student/v1/me/entitlements/`。

```typescript
interface Product { id: string; scope: "all_chinese"; name: string; priceFen: number; currency: "CNY"; permanent: true; expiresAt: null; purchaseAvailable: boolean; paymentChannels: { android: boolean; ios: boolean }; unavailableReason: string | null }
interface Entitlement { scope: "all_chinese"; active: boolean; permanent: boolean; expiresAt: null }
interface ProductList { count: number; next: null; previous: null; results: Product[] }
interface BusinessError { error: { code: string; message: string }; requestId: string }
```

范围暂只支持 `all_chinese`。内部服务见共享契约；`revoke_entitlement` 的 expected_fingerprint 比较目标来源及同范围全部来源状态。`release_opening` 默认不允许释放，必须显式传 True。`grant_entitlement` 的 actor=None 仅供已验证的内部兑换／付款服务；传入管理员则检查专用发放权限，后台不提供人工发放入口。

## Data Models（数据模型）

| 实体 | 字段 | 约束 |
| --- | --- | --- |
| Product | id、scope、name、price_fen、is_active、platform_product_id、platform_synced_price_fen、platform_sync_state、platform_synced_at | 范围唯一、仅全题库、价格正整数、改价清同步 |
| EntitlementSource | UUID、user、scope、source_type、source_id、expires_at、status、created_by、revoked_by、revoked_at、reason | 来源组合唯一、永久无到期、撤销不复活、服务写入 |
| OpeningReservation | user、scope、order_id、reserved_at、released_at、release_reason | 用户范围唯一；保留释放状态并复用行，历史留在审计 |
| AuditEvent | UUID、kind、user、actor、source、order_id、details、created_at | 创建后只读；只记录业务标识和状态 |

## Out of Scope（本模块之外）

- OS-1: 不连接真实支付平台，不创建订单或激活码；P06/P09/P10 调用统一服务。
- OS-2: 不修改账户模型、根路由、总配置、依赖或前端；主 agent 注册模块并整合。
- OS-3: 不提供人工付款成功、直接新增权益、期限续费、账号转移或自助退款入口。

## 操作与验收记录

运行 `python manage.py seed_product` 初始化商品。商品改价后在平台配置相同价格和映射，再由有同步权限的管理员确认；只有支付配置就绪才显示可购买。误发撤权在来源详情打开撤销预览，填写理由后确认；预览失效时重新核对。
