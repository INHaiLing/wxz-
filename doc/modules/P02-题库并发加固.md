# P02：题库并发加固

**Author:** 开发 agent P02；评审：主 agent／交叉开发 agent。

**Date:** 2026-10-02

**Status:** 已批准（来自阶段计划 FR-9）；代码与 SQLite 验收完成；PostgreSQL 并发验收待阶段 CI。

## Context（背景）

现有发布服务已锁定题目行并保留不可变修订，但普通编辑仅保护发布字段，两个旧表单可能覆盖彼此的草稿。发布确认页面只携带题目 ID，确认期间内容改变后仍可能发布未经确认的新草稿。

本模块给后台表单和确认操作加入签名、身份绑定及事务内指纹检查，不改变题库 API 或导入契约。

## Functional Requirements（功能要求）

- FR-1: MUST 已有题目编辑页面携带服务端签名的草稿指纹，绑定题目和当前管理员；缺失、篡改、过期或串用凭证拒绝保存。
- FR-2: MUST 保存已有草稿时锁定题目并比较旧草稿指纹；发生冲突返回 409 和可理解的表单提示，保留提交文字，禁止静默覆盖或返回未处理异常。
- FR-3: MUST 保存草稿沿用数据库当前发布标志及修订引用；只有发布／下架服务可修改这些字段。
- FR-4: MUST 发布和下架确认绑定当前管理员、操作、完整题目集合，以及草稿、发布状态、修订、更新时间指纹；凭证 30 分钟有效。
- FR-5: MUST 发布和下架在锁内重新核验确认指纹，任一题改变或集合被改则整批拒绝，不留下修订、状态或日志的部分更新。
- FR-6: MUST 保留后台发布权限、CSRF、只读修订、稳定 ID 和整批导入行为；直接内部发布服务允许无确认参数，后台确认必须提供签名凭证。

## Non-Functional Requirements（非功能要求）

- NFR-1 MUST SQLite 常规测试通过；PostgreSQL 使用独立连接验证实际事务竞争，不能用 SQLite 的锁行为证明行锁有效。
- NFR-2 MUST 签名只包含指纹和业务标识，不包含题干、答案或账号密钥；操作验证先检查管理员权限。
- NFR-3 MUST 单次发布／下架的签名核验与变更处于同一数据库事务，锁顺序以题目 ID 排序。

## Acceptance Criteria（验收标准）

### AC-1: (FR-1, FR-2, FR-3)

Given 两个管理员先读取同一草稿，When 先后提交不同修改，Then 首次成功、第二次 409，最新内容和发布修订保持正确。
### AC-2: (FR-1，NFR-2)

Given 缺失、篡改、过期、其他管理员／题目的编辑凭证，When 提交，Then 409 且草稿不变。
### AC-3: (FR-4, FR-5)

Given 一批已确认题目，When 内容、发布状态或选中集合改变后确认，Then 整批 409，所有题目、修订和日志均不变。
### AC-4: (FR-4, FR-5, FR-6)

Given 当前有效确认且拥有权限，When 发布／下架，Then 成功；没有权限及没有 CSRF 时仍被拒绝。
### AC-5: (FR-2、5，NFR-1、3)

Given PostgreSQL 独立事务竞争，When 编辑与编辑／发布与编辑交错执行，Then 锁内校验拒绝旧内容，不能覆盖或发布未经确认的更新。
### AC-6: (FR-6)

Given 现有种子、导入、预览及接口测试，When 执行回归，Then 通过且无需数据库迁移。

## Edge Cases（边界情况）

- EC-1: 新建题目没有旧草稿，不要求编辑凭证；新增权限和模型校验维持现有行为。
- EC-2: 只有发布状态变化、草稿内容未变时，编辑可以保存，必须保留最新发布状态；草稿指纹仅涵盖草稿字段。
- EC-3: 草稿被改回原值时允许编辑；发布确认额外包含更新时间，已发生的更新需要重新确认。
- EC-4: 冲突后表单保留原提交与原凭证，管理员应重新打开最新页面比较修改后再保存，不自动刷新凭证绕过冲突。
- EC-5: 下架不验证草稿合法性，损坏草稿仍可下架，但确认指纹必须匹配。
- EC-6: 大列表的“全选结果”在确认时展开成明确 ID 集合；重放 `select_across` 不能扩展确认范围。

## API Contracts（接口契约）

原 `/api/v1/` 不变。后台 `POST /admin/content/question/{id}/change/` 和 `POST /admin/content/question/` 新增隐藏字段：

```typescript
interface DraftEditInput { draft_token: string } // 管理员、题目、旧草稿摘要；30 分钟
type PublicationInput = { confirmation_token: string; confirm_publication: "publish_selected" | "unpublish_selected"; _selected_action: string[] };
type ConflictResponse = { status: 409; html: string }; // 表单／确认页面显示冲突，不写入
```

## Data Models（数据模型）

无数据库迁移；签名字段不入库。

| 数据 | 类型 | 约束 |
| --- | --- | --- |
| 草稿指纹 | SHA-256 字符串 | 稳定 ID 与全部可编辑字段 |
| 确认指纹 | SHA-256 字符串 | 草稿、发布标志、修订 ID、更新时间 |
| 签名凭证 | Django 时间戳签名 | 操作者、操作、ID 与指纹；最长 1800 秒 |

## Out of Scope（不在本模块）

- OS-1: 不增加新题型、学员认证或商业功能；不修改根配置和依赖。
- OS-2: 不改变导入预检流程，不物理删除历史。
