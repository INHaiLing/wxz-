# P11：接口契约与联调验收

**Author:** P11 开发 agent；Reviewer: 主 agent／模块 agent。

**Date:** 2026-10-02

**Status:** Approved（用户批准阶段计划与共享契约）；已实现、SQLite／PostgreSQL CI 通过，主 agent 交叉审核通过，阶段合入待办；真实甲方／渠道联调待办。

## Context（背景）

学员前端由甲方独立开发，需要完整、可执行的后端接口交接。P03～P10 的单模块验证无法替代题库、账号、权益、学习和交易之间的整体验收。

本模块只对照真实代码生成并校验契约，不提供运行时假登录或假支付。微信和支付外部响应仅在自动化测试隔离替换，实际账户及 Android／iOS 联调单列待办。

## Functional Requirements（功能要求）

- FR-1: MUST 交付版本化 OpenAPI 3.1 JSON，每个实际学员路径和方法包含认证、参数、请求、成功和业务错误结构及示例；不虚构未集成接口响应。
- FR-2: MUST 提供无新增依赖的契约校验命令与测试：逐一核对根路由、HTTP 方法、public／Bearer、请求幂等头、查询参数和枚举，检查内部引用、示例和实际响应。
- FR-3: MUST 完成「模板导入／发布→跨题型免费集合→微信测试登录→永久兑换→重复激活不耗码→多设备学习冲突→撤权／重放」全流程验收，跨模块权限使用真实服务。
- FR-4: MUST 验收随机轮次固定题序／旧修订及失权跳过、续学状态、支付创建／准备／消息／查单／退款及迟到消息；依赖模块合入后执行，不以运行时 stub 替代。
- FR-5: MUST 交付前端联调手册，说明 wx.login、401 重登、逐题状态 GET、模式／试学、分为单位的价格、签名字符串原样使用、成功后后端查单、幂等／409、失权展示和 iOS 渠道门控。

## Non-Functional Requirements（非功能要求）

- NFR-1 MUST 只使用标准库 json 自查及已锁定 Django／DRF 测试；每条合同路径方法都有机器覆盖，schema 不允许悬空 $ref。
- NFR-2 MUST 全流程测试使用临时数据库和测试秘密，不读写现有数据库或外部真实账号；SQLite 和 PostgreSQL CI 均通过。
- NFR-3 MUST 示例和文档不含真实令牌、AppSecret、微信 session_key、支付密钥或可用激活码；字段校验拒绝放大免费范围。

## Acceptance Criteria（验收标准）

### AC-1: (FR-1, FR-2, NFR-1)

Given 当前全部学员路由，When 执行契约检查，Then 无遗漏或幽灵路径，安全和 HTTP 方法与真实视图一致，引用及示例可校验。

### AC-2: (FR-3, NFR-2, NFR-3)

Given 导入后的草稿和独立学员，When 发布、试学、登录、兑换、收藏掌握及撤权，Then 内容版本和权限贯通，重复码不消耗，409 携带本人当前状态，旧成功重放不恢复已撤销权益。

### AC-3: (FR-4, NFR-2)

Given 随机轮次和真实模块交易状态机，When 重新发布、下架、支付重复通知、退款和迟到付款，Then 旧修订及鉴权正确、有效来源只发放一次且退款不被重放恢复。

### AC-4: (FR-5, NFR-3)

Given 甲方前端开发者，When 依手册对接，Then 清楚何时登录、何时提示开通、哪些字符串不能重序列化，以及真实 Android／iOS 和渠道待验收边界。

## Edge Cases（边界情况）

- EC-1: 非法 Bearer 在公开接口也 401；后台 Cookie 不能代替学员身份。
- EC-2: 无已发布题、错误分类、page_size／重复参数／错误题型不能扩大免费集合。
- EC-3: 已激活、购买处理中、同 key 异载荷、旧版本、撤权重试均保留正确业务状态。
- EC-4: 微信或支付不可用、iOS 未启用、平台消息重复或乱序不提供虚假开通。
- EC-5: 定义变动而文档未更新必须导致检查失败；不把模拟协议测试视作真实设备验收。

## API Contracts（接口契约）

`GET /api/student/v1/config/` 等实际路由的完整定义位于 `doc/api/student-v1.openapi.json`。统一错误：

```typescript
interface StudentError { error: {code:string;message:string;fields?:object};requestId:string }
interface Page<T> {count:number;next:string|null;previous:string|null;results:T[]}
interface ContractReport {operationCount:number;routeCount:number;errors:string[]}
```

校验命令 `python manage.py check_student_contract` 只读契约／路由；错误退出非零，不新增对外 HTTP 页面。

## Data Models（数据模型）

| 对象 | 类型 | 约束 |
| --- | --- | --- |
| OpenAPI document | JSON artifact | openapi=3.1.0；内部引用；路径／方法与实现一致 |
| ContractReport | 内存对象 | 错误列表、操作数／路由数；不存业务数据 |

本模块没有数据库实体或迁移；使用其他模块的真实模型进行隔离验收。

## Out of Scope（范围边界）

- OS-1: 不开发甲方前端、不请求或保存甲方秘密配置。
- OS-2: 不改认证、支付或题库的业务模块；发现缺陷交模块负责人修复。
- OS-3: 不声称已完成真实微信、Apple、备案、生产及甲方实际联调；这些仍需外部环境。
- OS-4: 不实现通用 JSON Schema 标准引擎；自查支持本契约使用的结构，完整外部工具验证可由甲方选择。

## Implementation and Validation（实施与验证）

契约记录当前 21 个实际学员路径、25 个 HTTP 方法。`write_student_contract` 读取实际根路由及 DRF 请求字段，响应定义由本模块维护；`check_student_contract` 会拒绝路由遗漏／幽灵路径、认证或幂等声明漂移、错误引用、未支持的 schema 断言和无效示例。有限校验器拒绝字符串冒充布尔／整数、额外题正文、非法日期及非 JSON 的 NaN／Infinity；不宣称替代完整 JSON Schema 引擎。
