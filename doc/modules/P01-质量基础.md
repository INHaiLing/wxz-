## Context（背景）

现有 Django 题库后台使用本机 SQLite，尚无 CI。交易、兑换及权益模块需要 PostgreSQL 行锁的实际验证；SQLite 测试通过不能证明交易并发可靠。

本模块建立隔离、可重复的质量检查入口，为后续模块提供 PostgreSQL 16 独立连接事务测试基础。保留 Windows 本地开发，同时由 Linux CI 验证生产数据库行为。

## Functional Requirements（功能要求）

- FR-1: MUST 保留全部现有依赖版本，补充 Python 3.14 可用的 psycopg 3 binary 与 cryptography，并完整锁定传递依赖。
- FR-2: MUST 提供只使用专用测试配置的跨平台检查脚本，执行依赖一致性、配置、迁移一致性、空库迁移与初始化以及 Django 测试。
- FR-3: MUST 在 GitHub Actions 的 Windows／Linux Python 3.14 上验证 SQLite；Linux 单独使用 PostgreSQL 16 服务执行同一后端检查及真实并发用例。
- FR-4: MUST 提供独立数据库连接下的行锁、提交可见性与事务回滚测试；SQLite 明确跳过这些 PostgreSQL 专属测试。
- FR-5: MUST 在 CI 运行现有 Node 前端测试和项目静态检查；任一命令失败使对应 job 失败。

## Non-Functional Requirements（非功能要求）

- NFR-1 MUST 使用临时 SQLite 文件、显式 TEST_DB_* 配置和独立测试数据库，不读取生产数据库配置；不得生成默认管理员密码。
- NFR-2 MUST 不在源码或 CI 输出中写入真实配置；测试密钥临时生成，PostgreSQL 测试凭据只用于一次性 CI 服务。
- NFR-3 MUST 限制 CI job 总时长 15 分钟；独立连接用例有超时、连接释放和异常传播，不靠等待时长猜测事务结果。

## Acceptance Criteria（验收标准）

### AC-1: (FR-1)

Given 干净 Python 3.14 环境，When 安装 requirements.txt 并执行 pip check／锁检查，Then 无缺失或非锁定业务依赖，psycopg 与 cryptography 可导入。
### AC-2: （FR-2，NFR-1）：Given 无本机 .env 和数据库，When 执行隔离检查脚本，Then 空库迁移、重复初始化及全部 Django 测试通过，正常开发数据库不被修改。
### AC-3: （FR-3、FR-4，NFR-3）：Given PostgreSQL 16，When 两个不同后端 PID 操作同一用户行，Then nowait 锁竞争准确返回 55P03，提交后新连接读取新值，回滚不留下新值。
### AC-4: （FR-3，FR-5）：Given 模块 PR，When Windows／Linux SQLite、Linux PostgreSQL、旧前端 job 执行，Then 每个检查均有可追溯结果；失败不显示为通过。

## Edge Cases（边界情况）

- EC-1: 包下载／版本冲突：安装失败直接阻止检查，不自动降级或更新业务依赖。
- EC-2: PostgreSQL 不可用或测试配置缺失：明确失败，不回退 SQLite 冒充并发验收。
- EC-3: 线程内部异常或超时：传播为测试失败，并关闭线程数据库连接。
- EC-4: 本机缺微信原生编译器：CI 执行可移植的 Node 测试与静态检查，原生编译仍使用已有本机命令，单独记录结果。

## API Contracts（接口契约）

不新增或修改业务 HTTP API。已有 `GET /healthz` 由现有测试验证；本模块提供命令行接口：

```text
python backend/scripts/verify.py --database sqlite
python backend/scripts/verify.py --database postgresql
```

成功退出码 0，任一子命令失败退出非 0。PostgreSQL 使用 `TEST_DB_NAME/USER/PASSWORD/HOST/PORT`，不接受生产 `DB_*` 作为回退。测试设置为 `config.test_settings`，禁止生产启动使用。

## 9. 实施与验收记录

已实现工作流、隔离检查脚本、完整依赖锁与独立连接事务基础。新增驱动 `psycopg/psycopg-binary 3.3.6`、加密依赖 `cryptography 50.0.2`，共 7 项直接依赖、17 项锁定依赖；原有版本保持不变。

官方依据：[psycopg 安装与平台支持](https://www.psycopg.org/psycopg3/docs/basic/install.html)、[cryptography 安装](https://cryptography.io/en/latest/installation/)。Python 3.14.7 / Windows 干净虚拟环境安装、驱动导入、Fernet 加解密和 `pip check` 已通过。

运行本机检查（在仓库根目录，先安装 requirements.txt）：

```powershell
& backend/.venv/Scripts/python.exe backend/scripts/verify.py --database sqlite
```

Linux 对应使用自己的 `.venv/bin/python`。脚本不要求 `.env`，SQLite 启动数据库由临时目录创建并回收；每次检查不创建管理员账户。`config.test_settings` 仅适用于测试，不能用于启动 Web 服务。

PostgreSQL 必须提供独立且可销毁的空数据库，以及可创建测试库的专用账户：

```powershell
$env:TEST_DB_NAME='chinese_study_ci'
$env:TEST_DB_USER='专用测试账户'
$env:TEST_DB_PASSWORD='专用测试凭据'
$env:TEST_DB_HOST='127.0.0.1'
$env:TEST_DB_PORT='5432'
& backend/.venv/Scripts/python.exe backend/scripts/verify.py --database postgresql
```

脚本会迁移并初始化该测试数据库，Django 测试创建并销毁 `test_<TEST_DB_NAME>`；不要填写生产库。本模块不自动创建 PostgreSQL 账户。CI 使用每个 job 独立的 PostgreSQL 16 服务，`TEST_DB_*` 不回退到 `DB_*`；连接超时 5 秒、锁等待 5 秒、单条 SQL 8 秒，辅助线程超时会请求取消 SQL。

本机证据：空库迁移、重复演示题／权限初始化、后端回归、前端 15 项测试、项目静态检查和原生 WXML 11 文件／WXSS 12 文件编译通过。原生编译不代表设备运行；GitHub 托管 runner 未安装微信编译器，CI 执行可移植检查。本机没有 PostgreSQL 服务，真实并发及 Linux／Windows runner 结果以本模块 PR 检查为准，不用 SQLite 结果替代。

工作流在 push、PR 和手动触发时运行；可在 GitHub PR 的 Checks 查看分开的 SQLite Windows、SQLite Linux、PostgreSQL 16 与历史前端结果。当前交叉评审已落实数据库等待和线程清理建议，最终测试数量与 CI 链接随 PR 补充。
