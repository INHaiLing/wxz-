# 后端开发阶段与任务

日期：2026-10-02。负责人：主 agent；评审：开发 agent 交叉评审。规格状态：已批准（用户确认实施分阶段计划）。实际状态以任务表和验收记录为准。

## 1. 背景与交付

现有 Django + DRF + Unfold 题库后台保留稳定题目 ID、发布修订、整批 XLSX 导入和后台权限。继续增加学员服务及业务后台；甲方自行开发学员前端。原 `miniprogram/` 是历史参考，保留回归检查。

基础 PR #1 尚未合并，因此所有阶段从包含现有后台及本规格的提交开始。主 agent 管理共享路由、配置、依赖、迁移整合和总文档；每个开发模块独立工作树、分支、数据库及服务端口。

## 2. 功能要求

- FR-1 MUST 保留后台 Session 接口；学员接口使用 `/api/student/v1/`，微信身份 `(appid, openid)` 唯一，Bearer 随机会话摘要存储、有效期 7 天；微信会话密钥服务端加密。
- FR-2 MUST 以当前已发布修订的排序及稳定 ID 确定免费集合。文学按分类、文言按篇目共用所有题型的第一页；页容量初始 20，后台可配置 1～100。客户端不能扩大授权。
- FR-3 MUST 提供全题库单商品，初始 1000 分、后台可改价；购买和兑换成功发放永久权益，来源可追溯、按来源撤销，永久权益不设自然到期。
- FR-4 MUST 阻止已有有效权益的新购买／新码兑换，提示“已激活”，不消耗码。成功请求重试只返回历史结果及当前授权，不重新激活已撤销来源。
- FR-5 MUST 在事务内按用户、开通占位、订单／码、权益来源顺序加锁。支付准备后保留占位，平台确定未付款最终状态后才释放；付款冲突留待核查。
- FR-6 MUST 激活码一码一人一次、永久可兑换；完整原码一次交付、确认领取后启用，下载失败作废旧批次重建；误发已兑码仅撤销对应权益且保留已用状态。
- FR-7 MUST 收藏和掌握独立、显式赋值，版本冲突返回 409；学习日按上海日期，重试去重；随机轮次固定题序及修订，续学存范围和题目 ID，所有读取重新鉴权。
- FR-8 MUST 使用官方虚拟支付、后端确认及发货、查询补偿、实际退款同步；未启用渠道拒绝支付准备，不能建立运行时模拟成功入口。
- FR-9 MUST 普通草稿编辑和发布确认检查并发变更；冲突整批拒绝，修改草稿不影响旧发布版本。
- FR-10 MUST 每个模块同 PR 更新说明、接口和验收记录，阶段同步 RRD、README 和 CHANGELOG。

## 3. 非功能要求

- NFR-1 MUST 通过现有后台和前端回归；新增权限、幂等、失败回滚和真实 PostgreSQL 独立连接并发用例。
- NFR-2 MUST 隔离管理／学员认证、账号数据；源码、日志、审计不记录原码、Bearer 令牌、AppSecret 或微信 session_key。
- NFR-3 MUST 空库迁移、初始化和配置检查可重复运行；提供 PostgreSQL 16 CI、生产启动和备份恢复路径。
- NFR-4 MUST 每个关键业务变更有操作者／来源／时间／请求标识；后台高影响操作检查权限、CSRF、理由和影响确认。
- 性能：本轮不承诺未提供规模的吞吐指标；接口有分页上限、外部请求超时、消息大小上限和有限批处理，部署验收记录实际环境。

## 4. 验收标准

- AC-1（FR-1，NFR-2）：Given 相同微信身份并发登录，When 创建会话，Then 只有一个用户；过期／停用／退出后拒绝令牌，学员不能访问管理员接口。
- AC-2（FR-2）：Given 同篇目多题型且总量大于容量，When 更换题型、页码或访问详情／随机／收藏／续学，Then 只获得统一免费集合内的内容；草稿不泄露。
- AC-3（FR-3～6）：Given 两个兑换／购买请求竞争，When 提交事务，Then 一次开通、没有超兑；重复开通不消耗新码，旧成功重试不恢复撤销权益。
- AC-4（FR-7）：Given 两设备同版本更新状态，When 同时写入，Then 一个成功一个冲突；请求重试不重复计数；随机轮次不重排，失去授权后内容受限。
- AC-5（FR-8）：Given 重复／乱序支付事件及并行查单，When 后端核验，Then 只发一次权益；退款后迟到通知不恢复；未开通渠道拒绝准备。
- AC-6（FR-9）：Given 两人编辑或确认后草稿被改，When 保存／发布，Then 不静默覆盖且整批不生效。
- AC-7（FR-10，NFR-1～4）：Given 空数据库和交付说明，When 初始化、导入、发布、试学、兑换、学习及恢复备份，Then 结果与接口文档一致，相关测试和 PR 有记录。

## 5. 边界情况

- EC-1 微信配置／渠道缺失、超时、无效 code：明确不可用或认证失败，测试替身仅用于测试。
- EC-2 导出中断：幂等重试定位待领取批次，不重发原码；作废并生成新批次。
- EC-3 支付取消或本地超时：不依据客户端释放占位；平台最终状态决定处理。
- EC-4 已付款但开通冲突：保留真实订单和核查记录，不吞款、不擅自改变退款政策。
- EC-5 发布、下架、撤权期间学习：历史保留，重新检查可读内容；无效续学位置返回原因和可访问起点。
- EC-6 原成功兑换被撤销后重放：返回历史成功和当前无权益，不重新发放。

## 6. 接口契约

原 `/api/v1/` 响应及 Session 权限不变。新增接口在版本化 OpenAPI 中逐模块定稿：登录／退出、公开配置和目录、题目、本人权益、兑换、本人订单与支付准备、学习状态／统计、随机轮次／续学。内容保持 `id/source/categoryId/articleId/type/tag/stem/answers/sortOrder/revision`。

```typescript
type BusinessError = { error: { code: string; message: string; fields?: object }; requestId: string };
type Entitlement = { scope: "all_chinese"; active: boolean; permanent: boolean; expiresAt: null };
type QuestionStateInput = { favorite?: boolean; mastered?: boolean; baseVersion: number };
```

写操作使用 `Idempotency-Key`；同键不同请求返回 409。无效令牌返回 401，不能降级匿名。受限内容返回 `403 ENTITLEMENT_REQUIRED`，不返回完整收费题干或答案。目录及免费顺序题允许匿名；个人、兑换、交易、随机接口需登录。支付平台消息使用独立安全入口。

内部共享服务：`has_active_entitlement(user, scope)`、`grant_entitlement(...)`、`revoke_entitlement(...)`、`published_questions()`、`free_question_ids(scope)`、`can_access_question(user, question)`。业务模块通过服务调用，不能各自判断订单／码解锁。

## 7. 数据模型约束

| 实体 | 关键字段与约束 |
| --- | --- |
| 微信身份／学员会话 | user、appid、openid；身份组合唯一；随机令牌摘要唯一、expires_at、revoked_at；加密 session_key |
| 商品 | scope 唯一、金额（分）、启用状态、平台商品映射与同步状态 |
| 永久权益来源／审计 | user、scope、来源类型与 ID 唯一、有效／撤销状态、expires_at=null、操作者及原因 |
| 开通占位 | user、scope 唯一、关联订单；外部未付款最终状态前不释放 |
| 激活码批次／码／兑换 | 原码摘要唯一、掩码、领取确认及禁用状态；单码唯一成功兑换、关联来源 |
| 订单／平台事件／补偿任务 | 本人归属、成交快照、平台流水、状态、唯一事件／任务键、重试及异常记录 |
| 学习状态／活动 | user+question 唯一、favorite/mastered/version；user+question+上海日期去重 |
| 随机轮次／续学 | user、类型化范围、模式、固定题目与修订引用、位置及版本 |
