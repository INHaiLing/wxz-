# 前端团队后端对接说明 v1

更新日期：2026-10-02。

最新业务规则：首期全题库商品成功购买或激活码兑换后获得永久使用权，不设置自然到期时间；该规则替代此前的 365 天使用期。激活码本身仍永久可兑换、一码一人一次。权益按来源记录，误发撤销或平台实际退款只处理对应来源。

试学与购买入口已确认：文学按文学分类、文言按每篇文章计算免费第一页，页内题数由后台配置。同一篇目的常识、字词和翻译共用一个免费题目集合，切换题型不额外赠送免费页。线上不需要扫码，用户看完免费内容后想继续学习，直接在小程序内开通／购买永久权益；界面由甲方前端实现。

重复开通规则已确认：已有同范围有效永久权益时，后端拒绝新购买和兑换另一枚码，前端提示“已激活”；不创建新的待支付订单，不消耗新码，也不重复发放权益。原成功请求的重试仍按幂等规则返回原处理结果及当前权益状态。

本文件面向负责微信小程序的前端团队。后端负责 API、Web 管理后台及接口约定；前端团队负责小程序页面与交互。本文件以当前代码为准，明确区分**已实现接口**与**拟定契约、尚未实现的模块**。文中的响应数据示例用于说明结构，不表示本机数据库一定存在同名记录。

## 1. 当前交付范围与联调边界

当前可运行的是 Django 题库管理后台、XLSX 导入预检、草稿编辑、发布/下架、发布修订记录，以及本文列出的四个受保护内容读接口。健康检查不需要登录。后台操作方式见 [最小后端使用说明](最小后端使用说明.md)。

**原四个内容接口仍仅供后台工作人员使用。** 已实现独立微信学员登录、商品及本人权益接口；学员目录／免费试学及激活码兑换已实现；订单、支付和学习同步按后续阶段推进。后台发布后，已有小程序不会自动切换数据源；前端团队需要接入正式学员接口并替换演示数据调用。

本机默认服务地址为 `http://127.0.0.1:8000`。正式联调域名、HTTPS、微信小程序合法域名配置与部署时间另行交付；手机上的 `127.0.0.1` 指向手机本身，不能直接访问开发电脑。当前未配置供独立 Web 前端使用的跨域访问能力。

核对代码：[总路由](../backend/config/urls.py)、[内容路由](../backend/content/urls.py)、[视图](../backend/content/api.py)、[字段与参数校验](../backend/content/serializers.py)、[权限](../backend/content/permissions.py)。

## 2. 已实现接口一览

请求内容接口时建议携带 `Accept: application/json`，避免浏览器内容协商返回 DRF 的 HTML 调试页面。以下内容路径保留末尾 `/`；`/healthz` 没有末尾 `/`。

| 方法与路径 | 用途 | 当前访问条件 | 成功响应 |
| --- | --- | --- | --- |
| `GET /healthz` | 进程存活检查 | 匿名可用 | `{"status":"ok"}` |
| `GET /api/v1/categories/` | 启用中的文学分类 | 后台登录且有 `content.view_category` | 分页列表 |
| `GET /api/v1/articles/` | 启用中的文言篇目 | 后台登录且有 `content.view_article` | 分页列表 |
| `GET /api/v1/questions/` | 已发布题目列表 | 后台登录且有 `content.view_question` | 分页列表 |
| `GET /api/v1/questions/{id}/` | 单道已发布题目 | 后台登录且有 `content.view_question` | 题目对象 |

`{id}` 是题目的稳定字符串 ID，使用英文字母、数字、下划线、连字符，区分大小写。内容接口只提供读取，不提供新增、修改、删除 API；管理操作使用现有 Web 后台。内容接口允许 `HEAD`、`OPTIONS`，仍需通过权限检查。`/healthz` 只接受 `GET`，不检查数据库或支付服务是否正常。

### 2.1 当前身份验证

内容接口使用 Django `SessionAuthentication`。用户必须同时满足：已登录、账号启用、`is_staff=True`、具备该接口对应的查看权限。仅有内容权限但不是后台工作人员，也不能读取。当前不接受 Bearer Token、微信登录 `code` 或自行构造的学员身份。

后台人员可在同一浏览器登录 `/admin/` 后查看内容接口，这是管理端调试方式。**不得将管理员 Cookie、管理员账号密码或后台会话嵌入小程序、分发给学员，或通过代理让学员共用后台身份。** 学员端登录使用下方独立接口，内容试学接口按 P05 交付。

## 3. 参数、过滤与分页

### 3.1 参数白名单

| 参数 | 分类/篇目列表 | 题目列表 | 题目详情 | 约束 |
| --- | --- | --- | --- | --- |
| `page` | 支持 | 支持 | 校验但不分页 | 默认 `1`；只接受 ASCII 数字组成的正整数 |
| `page_size` | 支持 | 支持 | 校验但不分页 | 默认 `20`；范围 `1`～`100` |
| `source` | 不支持 | 支持 | 支持过滤 | 仅 `literature`、`classical` |
| `categoryId` | 不支持 | 支持 | 支持过滤 | 非空；最多 64 字符；英文字母、数字、下划线、连字符 |
| `articleId` | 不支持 | 支持 | 支持过滤 | 非空；最多 64 字符；英文字母、数字、下划线、连字符 |
| `type` | 不支持 | 支持 | 支持过滤 | 仅 `fact`、`word`、`translation` |

参数名区分大小写，`categoryID` 与 `categoryId` 不同。每个参数只能出现一次。未知参数、重复参数、显式空值、非法枚举值都会返回 `400`；不能把空筛选项拼成 `source=`。`page=last`、`page=1.0`、`page=0`、`page_size=101` 都会报错，超大页容量不会自动截断成 100。

当前没有搜索、客户端排序、字段裁剪或总题库版本参数。不要发送 `search`、`ordering`、`fields`、`format=json` 等未定义参数；JSON 响应通过 `Accept` 请求头选择。

多个题目过滤条件按“同时满足”处理。合法但不存在的分类/篇目 ID 返回空列表；如 `source=literature&articleId=quanxue` 没有匹配结果，也返回空列表，不当作参数格式错误。详情接口同样应用过滤；存在的题目若不满足过滤条件，返回 `404`。详情调用通常只需 ID，无需附加分页参数。

### 3.2 排序与分页响应

- 分类、篇目：按当前 `sort_order` 升序，再按 `id` 升序。
- 题目：按**已发布修订**的 `sort_order` 升序，再按稳定题目 `id` 升序。
- 前端应保持服务端顺序。相同排序值下用 ID 确定顺序，不使用数组下标作为题目身份。

三种列表统一返回：

```json
{
  "count": 1,
  "next": null,
  "previous": null,
  "results": [
    {"id": "pre-qin", "name": "先秦文学", "sortOrder": 0}
  ]
}
```

`count` 是当前过滤条件下的可见记录总数。`next`、`previous` 是相邻页的绝对 URL，没有相邻页时为 `null`。`results` 是当前页数组。空结果的第一页返回 `200`、`count: 0`、`results: []`；超过有效页范围返回 `404`。客户端按当前环境的可信 API 域名访问分页地址，不硬编码本机地址。

当前分页是普通页码分页，没有跨多次请求锁定全题库的快照令牌。后台发布、下架或改排序后，不同时间请求的页内容可能变化；前端需要支持刷新，并可按稳定 ID 去重，不能把某一次列表的下标当作长期学习位置。

**这里的默认 20 条、最大 100 条与未来“分类第一页免费”没有授权关系。** 当前接口面向有权限的后台人员，尚未实施免费与付费内容区分。

## 4. 成功响应字段

当前没有统一的 `code / message / data` 外层包装。列表是分页对象，题目详情直接返回题目对象。所有下面列出的字段均为只读输出。

### 4.1 分类与篇目

| 对象 | 字段 | JSON 类型 | 含义 |
| --- | --- | --- | --- |
| 分类 | `id` | string | 稳定分类 ID，最多 64 字符 |
| 分类 | `name` | string | 分类名称 |
| 分类 | `sortOrder` | integer | 非负排序值 |
| 篇目 | `id` | string | 稳定篇目 ID，最多 64 字符 |
| 篇目 | `title` | string | 篇目名称 |
| 篇目 | `sortOrder` | integer | 非负排序值 |

篇目列表的 `results` 示例为 `[{"id":"quanxue","title":"劝学","sortOrder":0}]`。目录接口没有题目、答案、题量、是否免费或是否已购买字段；启用的空目录也可能返回。不要依据目录是否出现推断该目录已有发布题目。

### 4.2 题目列表项与详情

```json
{
  "id": "lit-shijing",
  "source": "literature",
  "categoryId": "pre-qin",
  "articleId": null,
  "type": "fact",
  "tag": "文学常识",
  "stem": "《诗经》收录{{0}}篇。",
  "answers": ["305"],
  "sortOrder": 0,
  "revision": 1
}
```

| 字段 | JSON 类型 | 约定 |
| --- | --- | --- |
| `id` | string | 稳定题目 ID；修改题干、排序、发布和下架都不换 ID |
| `source` | string | `literature` 文学常识；`classical` 文言文 |
| `categoryId` | string 或 null | 文学分类 ID；文言题为 `null` |
| `articleId` | string 或 null | 文言篇目 ID；文学题为 `null` |
| `type` | string | `fact` 常识、`word` 字词、`translation` 翻译 |
| `tag` | string | 题目标签，可为空字符串 |
| `stem` | string | 题干，含答案索引占位符 |
| `answers` | array of string | 非空答案数组，各项为非空文字 |
| `sortOrder` | integer | 已发布版本的非负排序值 |
| `revision` | integer | 当前题目的发布修订号；不是全题库统一版本号 |

文学题为 `literature + fact + categoryId`；文言题为 `classical + articleId`，题型可以是上述三种。不要从 ID 前缀、分类名称或 `tag` 推断来源和题型，应使用明确字段。

题干 `{{0}}` 对应 `answers[0]`，`{{1}}` 对应 `answers[1]`，依此类推。索引从 0 连续开始，每个答案都有对应占位符，同一索引可以在题干中重复出现。示例：`"{{0}}提出{{1}}，{{0}}是思想家。"` 与 `["孔子", "仁"]`。不得假定每题只有一个答案，也不要依赖固定七列或固定填空数量。

前端团队自行决定题卡布局、填空交互与视觉样式；占位符与数组对应关系属于数据契约。题干和答案按文本处理，不将数据库中的任意内容直接作为可执行 HTML 或脚本。

### 4.3 发布快照与可见性

题目正文、答案、来源、归属、题型、标签、排序及修订号均来自 `published_revision`。后台仅编辑或导入草稿不会改变已返回给读取接口的发布内容；重新发布后，接口才读取新修订。

列表与详情都仅暴露：已上架、有有效且属于该题的发布修订、发布修订关联的分类/篇目仍启用的题目。草稿、下架题或不满足这些条件的题目不出现在列表中，详情返回 `404`，不返回草稿内容。当前不提供读取历史修订的 API。

分类名称、篇目标题与它们自己的排序来自当前启用目录，并非题目的独立历史快照。`revision` 不能当作全站缓存版本或权益状态版本；当前也未提供 ETag 或条件请求契约。

## 5. 当前错误响应

以下 JSON 示例在当前 `zh-hans` 配置、`Accept: application/json` 下核对。前端优先使用 HTTP 状态及对象结构处理错误，不把中英文提示原文当稳定的机器错误码。当前未实现统一业务错误码字段。

| 状态 | 典型情况 | 实际响应示例 |
| --- | --- | --- |
| `400` | 未知参数 | `{"categoryID":["不支持的查询参数。"]}` |
| `400` | 参数重复 | `{"page":["同一查询参数只能提供一次。"]}` |
| `400` | 每页超过上限 | `{"page_size":["请确保该值小于或者等于 100。"]}` |
| `400` | 非法整数 | `{"page":["请填写合法的整数值。"]}` |
| `400` | 非法枚举 | `{"source":["“wrong” 不是合法选项。"]}` |
| `403` | 没有有效后台登录会话 | `{"detail":"身份认证信息未提供。"}` |
| `403` | 已登录但不是可访问的后台账号或缺少查看权限 | `{"detail":"需要启用的后台账号及对应的内容查看权限。"}` |
| `404` | 匹配到详情路由，但题目不存在、下架或过滤不匹配 | `{"detail":"No Question matches the given query."}` |
| `404` | 列表页码超出范围 | `{"detail":"无效页面。"}` |
| `405` | 通过鉴权等检查后，对内容接口使用 POST | `{"detail":"方法 “POST” 不被允许。"}` |

注意处理顺序与边界：

- 权限检查先于查询参数校验。未登录时发送错误参数，通常先得到 `403`，不会先得到 `400`。
- 内容接口的 POST/PUT/PATCH/DELETE 没有实现。在真实 Session 请求中，缺少 CSRF 校验信息可能先得到 `403`；只有通过前置检查后才会得到方法不允许的 `405`。不要为测试写方法给小程序接入管理端 Cookie。
- `/healthz` 不是 DRF 内容视图；HEAD/POST 的视图结果为 `405`、`Allow: GET`、空正文，不能按 JSON 强制解析。实际 HTTP POST 还可能先被 Django CSRF 中间件拒绝。
- 未命中路由的路径，例如含 `.` 的题目 ID、拼错的路径，可能返回 Django HTML `404`；部署代理或服务器异常也不保证 JSON。先检查状态码与 `Content-Type`，保留网络失败的兜底提示。
- 内容接口目前没有“学员未登录”“权益被撤销”“需要购买”等专门返回值。不能把所有 `403` 解释成付费提示。

## 6. 本机 curl 联调示例

先按 [最小后端使用说明](最小后端使用说明.md) 启动服务。以下示例适用于 Windows PowerShell，使用 `curl.exe` 避免命令别名差异；不包含任何实际账号、Cookie 值或密钥。

```powershell
$ApiBase = 'http://127.0.0.1:8000'

# 匿名健康检查：预期 200，正文 {"status":"ok"}
curl.exe -i -H 'Accept: application/json' "$ApiBase/healthz"

# 匿名访问内容：预期 403
curl.exe -i -H 'Accept: application/json' "$ApiBase/api/v1/questions/"
```

需要查看成功响应时，最简单的方式是让有查看权限的后台人员在登录后台的同一浏览器打开内容接口。若后端人员使用 curl 调试，可使用**仅本机、本人授权的后台测试会话 Cookie 文件**。由本机安全配置提供文件路径，Cookie 文件不进入 Git、交接附件、小程序或共享文档；本节不提供学员身份登录方案。

```powershell
# STAFF_API_COOKIE_JAR 只保存本机测试 Cookie 文件的路径，不是 Cookie 内容。
# 未配置有效文件与后台会话时，不应预期下面的请求成功。
$StaffCookieJar = $env:STAFF_API_COOKIE_JAR
if (-not $StaffCookieJar -or -not (Test-Path -LiteralPath $StaffCookieJar)) {
    throw '请先由后端联调人员配置本机后台测试会话文件。'
}

# 分类与篇目：预期 200，分页结构
curl.exe -i --cookie "$StaffCookieJar" -H 'Accept: application/json' "$ApiBase/api/v1/categories/?page=1&page_size=20"
curl.exe -i --cookie "$StaffCookieJar" -H 'Accept: application/json' "$ApiBase/api/v1/articles/?page=1&page_size=20"

# 文学题列表：预期 200；尚未发布题目时 results 为空
curl.exe -i --cookie "$StaffCookieJar" -H 'Accept: application/json' "$ApiBase/api/v1/questions/?source=literature&type=fact&page=1&page_size=20"

# 详情：输入上一个列表 results 中实际返回的 id
$QuestionId = Read-Host '输入已发布题目的 id'
curl.exe -i --cookie "$StaffCookieJar" -H 'Accept: application/json' "$ApiBase/api/v1/questions/$QuestionId/"

# 非法分页上限：预期 400
curl.exe -i --cookie "$StaffCookieJar" -H 'Accept: application/json' "$ApiBase/api/v1/questions/?page_size=101"

# 重复参数：预期 400
curl.exe -i --cookie "$StaffCookieJar" -H 'Accept: application/json' "$ApiBase/api/v1/questions/?page=1&page=2"
```

用分类或篇目 ID 过滤时，从目录接口选取实际 ID，再发送 `categoryId` 或 `articleId`。后台初始化的数据可能都是草稿；没有发布题目时列表为空是正常结果。

| 免费试学 | 文学按分类、文言按篇目，每个分类的**学习列表第一页**免费；页内题数由后台配置，不固定写成 5 题。文言同篇目的全部题型共用一个免费集合，由后端按已发布排序选出 | 未实现；分类口径已确认，最终配置与授权响应字段待接口定稿；不能以客户端 `page=1`、增大 `page_size` 或切换题型扩大免费范围 |
| 商品与价格 | 首期一个全题库商品，初始价格 10 元，管理员可调整；成功购买后获得永久使用权。拟定金额以整数分传输，价格及可购买状态从后端获取 | 未实现；订单保存成交价、永久权益规则等快照，改价不改变旧订单；取消到期和续期堆叠逻辑。已有有效永久权益时拒绝新下单，提示“已激活”，重复开通规则已确认 |
| 激活码 | 一码仅限一名用户成功兑换一次；**永久可兑换**，不设兑换截止期；兑换获得对应商品的永久使用权。已有有效永久权益时拒绝兑换另一枚码，提示“已激活”，新码保持未使用。线下独立收款后管理员发码，小程序提供兑换，也支持免费赠送 | 未实现；后端负责限频、原子兑换、幂等与权益发放，原成功请求重试不重复消耗或发放。具体业务状态码随接口定稿，不将线下发码流程描述为已通过平台审核 |
| 支付与订单 | 线上无需扫码。用户看完免费内容后继续访问受限内容，需要开通永久权益；前端展示开通入口，使用商品和订单接口调用微信小程序虚拟支付。后端创建订单、生成参数、验证平台事件、查单补偿并发放永久权益，用户接受 iOS Apple 支付 | 未实现；旧账号截图显示虚拟支付尚未开通，Apple 能力未确认，正式联调前核对最新状态。不以客户端支付 success、截图或本地存储认定已付款；取消/失败/处理中/已支付等状态以正式接口定义为准 |
| 来源权益、退款与误发撤销 | 订单、激活码等来源分别留痕，统一计算当前权益。用户允许管理员撤销已兑换误发码对应的权益，**保留其他订单/兑换来源的有效权益**；平台实际退款仍需同步处理 | 未实现；后端事务处理、记录操作者/原因/对象/结果并审计，不能只清空“会员”布尔值；前端刷新权益与授权内容，不负责自行重算或回写付款结果 |
| 学习记录同步 | 拟定收藏、掌握状态、学习位置等使用稳定题目 ID，与内容发布修订分开保存；异步同步应具备重试、幂等和明确冲突处理 | 未实现；同步字段、离线队列、跨设备规则、演示记录迁移范围尚未冻结，不把本地保存成功显示成云端同步成功 |

上表中的“权益来源”是某笔订单或某次兑换的出处，与题目字段 `source=literature/classical` 含义不同，不能混用。误发撤销与禁用未兑换的码也是不同操作；撤销后按仍有效的来源计算可访问范围，学习历史和审计记录保留。

永久权益没有自然到期，但对应来源仍可因误发撤销或平台实际退款而失效；只要还有其他有效来源，用户继续拥有永久使用权。所有来源均无效时回到免费试学范围，不删除学习历史，也不把已使用的激活码恢复为可兑换。

只有在当前已无同范围有效永久权益时，才允许重新购买或使用一枚未使用的新码开通；有其他有效来源时仍提示“已激活”。同一账户同时提交多个新码或购买请求，也不能先检查后重复开通，后端需在事务及并发控制中完成授权判断与业务写入。前端隐藏购买按钮不能代替该检查；已实际付款的订单通知仍应如实验签、记录和核查，不因拒绝新下单规则而丢弃付款结果。

免费集合按文学分类或文言篇目的全部已发布题目排序确定，再应用题型筛选；例如《劝学》只选出一次前 N 道免费题，字词与翻译各自的第一页不会重新获得 N 道。若某个题型在该集合中没有题目，切换到该题型也不能新增免费题目。列表、详情、收藏、随机和续学复用同一集合及永久权益校验。

用户请求超出免费范围且没有有效永久权益时，后端返回受限状态及可购买信息，具体字段随学员接口冻结；不得先返回完整受限题目和答案再依靠前端遮罩。前端展示开通提示、获取当前商品信息、发起订单和官方支付，并在后端确认开通后继续访问；已有永久权益的用户可直接读取授权内容。无需先逐题完成免费页才允许购买，也不新增扫码购买页或二维码关联接口。独立线下收款后发码、平台只兑换的规则继续保留。

## 8. 前端接入与缓存约定

1. 将题库读取封装为异步请求，页面处理加载、空列表、网络失败、权限变化与重试。切换分类、题型或账号时，防止旧请求的迟到响应覆盖新选择。
2. 使用稳定 `id` 关联题目与学习记录；`revision` 可帮助识别题目内容变化。不要使用数组下标、题干文字或自造 ID 匹配后台记录，也不要将不同修订的题干与答案混合缓存。
3. **正式付费题目和完整答案不能继续打包在小程序静态资源里。** 前端遮罩、隐藏按钮和本地“是否购买”字段不构成服务端授权。演示数据与生产数据分开，生产按需获取后端授权内容。
4. 缓存策略待学员接口实现后与后端冻结：按用户隔离，按配置刷新；退出、换账号、退款或撤销后，清理不再可访问的内容，重新核验权限。永久权益无需自然到期处理，缓存命中仍应按约定核验当前授权状态。
5. 支付、兑换、学习写入的重试与幂等依正式接口实施，不自行假定“超时等于失败”并重复创建业务。客户端支付回调只用于推进查询和展示，后端确认才决定权益是否生效。
6. 前端可先基于本文字段结构制作带显著标识的模拟数据与请求适配层；未实现模块的 mock 不能作为真实联调成功或生产可用证明。

## 0.2.0 学员身份与权益已实现接口

下列接口统一前缀 `/api/student/v1/`，JSON 响应，尾部斜杠必须保留；与上文后台 Session 接口分开。

| 方法与路径 | 请求／响应 | 访问条件 |
| --- | --- | --- |
| `POST auth/wechat/` | `{"code":"wx.login 获取的临时代码"}` → `{token,expiresAt,user:{id}}` | 请求不携带旧 Bearer；服务端调用 code2session |
| `POST auth/logout/` | 当前会话退出，204 | 当前 Bearer |
| `GET products/` | 分页形状 `results` 包含 id、priceFen、permanent、purchaseAvailable、paymentChannels | 可匿名；无效 Bearer 返回 401 |
| `GET me/entitlements/` | `{scope:"all_chinese",active,permanent,expiresAt:null}` | 当前 Bearer |

登录后请求头为 `Authorization: Bearer <token>`；有效期 7 天，退出或账户停用立即失效。不要给学员接口传管理员 Cookie。微信 AppSecret、加密密钥只在服务端环境配置；缺少配置返回 503，代码不存在模拟登录入口。登录令牌仅在创建时返回，日志和上报不得包含令牌。

`products/` 的 `purchaseAvailable=false` 时禁止调用付款；`unavailableReason` 表示商品停用、平台同步未确认或渠道未开通。价格以分计，是否开通始终查询本人权益；商品接口可用不代表已完成真实 Android／iOS 支付验收。

技术错误统一 `{error:{code,message,fields?},requestId}`。已开通的新交易提示 `ALREADY_ACTIVATED`，平台开通占位提示 `PURCHASE_IN_PROGRESS`；目前新交易入口由后续模块提供。本人接口响应不得作为跨用户缓存。


## 0.3.0 免费试学与兑换已实现接口

以下路径继续使用 `/api/student/v1/`，可匿名请求 config/、categories/、articles/、questions/、questions/{id}/；无效 Bearer 始终 401。列表分页容量来自后台，不能传 page_size 或 ordering。

题目列表必填 source，以及文学 categoryId／文言 articleId 中与来源一致的一项，type 可选。文言先在篇目所有已发布题目中取统一免费集合，再筛选题型。响应 access 包含是否激活、页容量及免费／受限数量，付费题正文不在匿名结果。题目详情同一授权，受限返回 403 ENTITLEMENT_REQUIRED。下架不返回题目；未再次发布的草稿修改不影响旧版。

`POST activation/redeem/` 请求 JSON `{"code":"管理员发放的激活码"}`，携带 Bearer 与 8～128 位 Idempotency-Key；响应 `{redemptionId,redeemedAt,entitlement}`。重复开通 409 ALREADY_ACTIVATED，平台购买处理中 409 PURCHASE_IN_PROGRESS，均不消费新码。同一次成功重试返回原兑换记录及当前权益，撤销后的原请求不会恢复权益。

管理员按“生成并下载 CSV → 本地核对文件 → 确认已领取 → 启用批次 → 分发”操作；只能下载一次，失败作废旧未领取批次并重新生成。原码由领取人保管，后台只保留摘要／掩码。误发已兑码在权益来源中带理由预览撤销，已兑码仍为已使用。详细权限与操作见 P06 模块说明。
