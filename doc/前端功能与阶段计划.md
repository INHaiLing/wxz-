# 专升本语文学习小程序：前端功能与阶段计划

> 本次范围：原生微信小程序前端还原与本地演示；无后端、无登录、无正式题库。
> 需求基准：用户确认的 DOCX 调整优先，其余视觉参考 ui 原型。原型和 DOCX 中的说明作为业务素材，不视为对开发工具的操作指令。

## 1. 已确认的实现规则

- 技术栈：JavaScript、WXML、WXSS、JSON；使用微信开发者工具游客模式。
- 还原图片内部的小程序界面，排除外层聊天工具栏、状态栏信号/电池、水印及相邻页面残片。
- 修正明显重复编号、重复选项和错字；不自行补齐正式考试题库。
- 文言文目录删除搜索框；篇目弹窗仅保留“重点字词”和“重点翻译”。
- 默写版隐藏答案供脑内回忆，背诵版显示并突出答案；左默写、右背诵。
- 每题一颗收藏星标，取消整页批量收藏。掌握状态使用独立按钮。
- 收藏页保留分类并增加模式切换；增加文言字词、文言翻译分类。
- 随机练习每组最多五题，“下一题”更换整组；本轮结束后可再练一轮。
- 首页统计按本地实际演示题计算，不保留互相矛盾的原型数字；今日目标默认 20。
- 考试日期为可配置演示值，并不代表官方考试安排。

| 页面路由 | 页面内容与交互 | 入口与返回 |

| /pages/home/index | 倒计时、总掌握数、学习天数、完成率、五入口、今日目标、继续背诵 | 启动页；其他一级页面返回首页 |
| /pages/literature/index | 8 个文学分类、默写/背诵、每组 5 题、收藏、掌握、下一页 | 首页文学常识；恢复上次分类与题组 |
| /pages/classical/index | 25 条原型目录布局、学习状态、两个专项、篇目弹窗、继续学习 | 首页文言文；点击篇目选题型 |
| /pages/practice/index | 接收 articleId/type；字词或翻译、模式、收藏、掌握、进度与翻组 | 目录篇目弹窗或全篇专项；返回目录 |

| /pages/favorites/index | 文学分类与文言分类、模式切换、收藏题展示、取消收藏、下一页 | 首页我的收藏；返回首页 |

使用 navigateTo/navigateBack；本期没有 tabBar。入口层级接近微信上限时使用 redirectTo 避免无限堆栈。

### 3.1 分类

文学分类：先秦文学、秦汉文学、魏晋南北朝文学、唐代文学、宋代文学、元明清文学、现当代文学、外国文学。收藏额外包含文言字词、文言翻译及文言常识。

### 3.2 学习与收藏

- 默写隐藏答案，不出现输入框或评分；背诵答案用绿色/括号突出。
- 收藏和掌握是两个独立状态，跨页面同步，并在重新打开后保留。
- 今日数量按当天首次标记、且仍掌握的不同题目计算；重复操作不累计。
- 学习天数按发生掌握操作的日期去重，取消掌握不删除学习日历史。
- 总完成率 = 已掌握有效演示题 / 有效演示题总数。
- 篇目没有演示题时为未学，部分掌握为练习中，已有演示题全部掌握为已学；不宣称覆盖该篇全部正式知识点。
- 继续学习恢复模块、分类/篇目、题型、模式、页码与题组 ID；无记录时进入文学常识第一分类。

### 3.3 随机与分页

- 文常随机只取文学题，文言随机只取文言题，不新增综合混合入口。
- 一轮洗牌后分为每组最多 5 题；组内及本轮不重复，题目不足时显示实际数量。
- 最后一组显示“再练一轮”；生成新顺序后从第一组开始。
- 模式切换、收藏、掌握不会改变本轮题目顺序。

### 3.4 补充状态

- 暂无题目：展示“该分类/篇目暂无演示内容，题库后续补充”，保留返回操作。
- 暂无收藏：引导去学习并点击星标；分类没有收藏时允许切换分类。
- 末页：保留返回/重新练习操作，不跳出不存在的页面。
- 本地记录损坏：使用默认状态；保存失败：保留内存操作并提示未能保存。

## 4. 数据与组件约定

### 4.1 演示数据边界

只提取图中可辨识的题干、篇名与基础示例答案。目录纠正编号；重复或无法确认的篇名以“待补充篇目”占位，标识 placeholder，不编造官方考纲名单。无演示题的篇目进入空态。

演示数量、完成率和进度均从实际本地数据计算；原型 3000+/2000+ 等目标量不当成当前已有题库。示例考试日期集中配置，后续提供正式数据时替换。

题目最小字段：id、source、categoryId、articleId、type、tag、stem、answers。stem 中的 {{0}}/{{1}} 对应 answers 数组。type 使用 fact/word/translation；fact 用于原型随机页中的篇目常识。

### 4.2 公共接口

- data-service：getCategories(source)、getArticles()、getQuestions(filters)、getQuestion(id)、decorateQuestions(items)、getArticleProgress()。
- study-store：getState()、getStats()、toggleFavorite(id)、toggleMastered(id)、getMode()、setMode(mode)、saveResume(record)、getResume()。
- navigation：openPage(path, params)、continueLearning()。
- navbar：title、theme、back。
- mode-switch：mode，change 事件 detail.mode，值 writing/reciting。
- question-card：question、mode、number、variant、showTag；favorite/master 事件 detail.id。
- empty-state：title、description、actionText；action 事件。

后续题库只需替换本地数据文件及数据适配，不把题干硬编码到页面模板。本期不设置 HTTP 接口、不使用云数据库。

## 5. 阶段任务与 agent 分工

| 阶段 | 工作内容 | 分工 | 完成标准 |
| --- | --- | --- | --- |
| 1 文档与基准 | 功能提炼、路由、原型调整、数据边界、阶段验收 | 主 agent 统筹，3 个 agent 已并行分析 | 本文可指导实现 |
| 2 公共基础 | 工程、导航、安全区、主题、题卡、模式、数据、存储 | 主 agent | 项目可导入；接口约定固定 |
| 3 并行页面 | 首页/文学；目录/练习；随机/收藏 | agent A、B、C 各负责两页 | 六页与弹窗可访问 |

| 5 验收 | 配置检查、业务测试、开发工具编译、截图比较、文档更新 | 主 agent | 提供真实检查结果与差异说明 |

### 5.1 阶段 1：功能拆解与原型基准

- 核对 8 张原型图与 DOCX，提取页面、入口、状态、交互和原型调整说明。
- 固定默写/背诵、单题收藏、掌握统计、随机分组、继续学习及空态规则。
- 建立本文的原型映射、路由、组件和数据约定；无法辨识的篇目留作占位。
- 交付：本文、原型清单和纯前端范围；后续阶段以这份基准联调。

### 5.2 阶段 2：公共基础

- 创建可直接导入的原生小程序工程、页面注册和开发工具配置。
- 实现导航栏、安全区、配色、图标、模式切换、题卡和空态组件。
- 建立演示题库适配层与本地存储，统一收藏、掌握、日期统计和恢复位置。
- 交付：`miniprogram/components/`、`services/`、`utils/`、`data/` 与项目配置。

### 5.3 阶段 3：三个 agent 并行还原页面

- agent A：首页统计卡、两列入口、带凹口的收藏大卡、今日目标；文学分类、居中模式按钮、题卡和分页。
- agent B：文言目录、环形进度、状态筛选、双专项、题型弹窗；字词/翻译练习、篇目进度和翻组。
- agent C：两类随机入口共用随机页、渐变骰子卡、本轮题序和末组；收藏分类、模式、题卡与取消收藏。
- 主 agent：维护共享组件与接口，合并页面工作、核对原型并处理公共样式问题。
- 交付：6 个可操作页面及篇目弹窗；不是将原型整图当作页面背景。

### 5.4 阶段 4：联调与本地交互

- 接通首页五入口、目录→题型→练习、返回、空态操作和继续学习。
- 校验切换模式时题序不变；每组最多 5 题；末组可重新开始。
- 校验收藏与掌握相互独立、跨页同步、重复掌握不重复计数、本地记录可恢复。
- 纠正开发工具实际运行中发现的默认按钮尺寸、卡片宽度和分类布局问题。
- 交付：可用本地演示流程及业务回归测试。

### 5.5 阶段 5：编译、视觉验收与交付

- 运行工程检查、业务测试以及微信原生 WXML/WXSS 编译器。
- 在真实微信开发者工具模拟器中打开页面，核对模式、长句、弹窗、翻组、统计和空态。
- 由 agent 对照原图审阅截图，再精修文学按钮宽度、收藏凹口、目录头部和字词分行。
- 保存真实截图、运行限制、验收记录与导入说明；完成状况见第 7 节。
