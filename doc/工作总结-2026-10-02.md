# 2026-10-02 工作总结

阶段版本：`v0.1.0` 为首个功能里程碑，收工文档修正归入 `v0.1.1`。本次整理当前工作区已经完成的前端、独立题库后台及配套文档，形成第一份完整的代码版本。原型和设计历史一同保留，便于后续核对。

## 今天完成了什么

### 小程序前端

- 从原型提炼功能，建立分阶段开发与验收文档。
- 完成首页、文学常识、文言目录、专项练习、随机练习、收藏 6 个页面及 5 个公共组件。
- 多 agent 分页协作，将全部界面统一到用户确认的「青墨雅韵」设计。
- 保留默写自测、背诵全览、收藏、掌握、随机题组、继续学习和本地统计；修复实际模拟器中的卡片布局、答案/占位线换行和图标颜色问题。
- 保存新版 16 张实际截图及页面总览，记录小屏、长句、弹窗、空态和底部操作栏验收结果。

### 独立题库后台

- 完成 Django + DRF + Unfold 本机管理后台，支持分类、篇目和题目维护。
- 完成 XLSX 模板、上传预检、冲突检查、整批导入、重复导入与导出。
- 分离草稿保存和正式发布，保留稳定题目 ID 与不可变发布历史，支持下架。
- 建立查看、编辑、发布权限组，以及需要管理员会话和查看权限的查询 API。
- 提供初始化、启动脚本、依赖版本锁定和操作说明；不提供默认管理员密码。

## 版本如何保存

- 工作分支：`codex/qingmo-v0.1.0`；通过合并请求进入 `main`。
- 首批提交分为前端功能、题库后台、版本与总结文档三组；随后增加文档归档修正，使用 Conventional Commits。
- 阶段标签：保留已发布的 `v0.1.0`；文档归档修正使用 `v0.1.1`。同名标签后续不移动。
- 根目录 `VERSION`、前端 `package.json` 及锁文件统一为 `0.1.1`；后端依赖由 `backend/requirements.txt` 独立锁定。
- 修复版本使用 `0.1.x`，下一阶段功能使用 `0.2.0`；每次阶段交付同步更新 `CHANGELOG.md`。日常改动进入功能分支，检查通过后合并，避免直接重写 `main` 历史。

## 下次接着做

不依赖收费、支付等问卷答案的工作可以先安排：

1. 给草稿编辑和发布确认增加版本冲突提示，避免多人操作时覆盖旧内容或发布未确认的新草稿。
2. 提供完整数据库备份、校验与恢复命令，并在独立数据库演练；当前只有手工备份说明。
3. 增加内容工作台和质量提示，如待发布数量、空篇目、不同 ID 的相似题；不自动删除内容。
4. 后续补充修订对比和恢复为草稿、运行日志、统一回归入口与 CI、真实 PostgreSQL 并发和迁移验证。

需要业务答案后继续：提供正式题库样例，确认学员身份、访问权益与支付激活码规则，再进行前后端联调。当前查询 API 面向后台人员，不能直接当作学员接口开放。准备上线时还需在真实手机上验收字体、胶囊、交互和滚动，并验证生产数据库及部署。

当前小程序继续读取本地 mock，后台发布不会自动更新小程序；支付、激活码、学员登录、学习同步及公网部署未完成。
