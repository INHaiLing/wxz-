# 题库整理与交付说明 v1

日期：2026-10-02。适用于当前题库管理后台。

题库统一使用我方提供的 [题库导入模板-v1.xlsx](题库导入模板-v1.xlsx)。甲方按本说明整理即可，无需再选择或确认文件格式。甲方负责提供正式题目、准确答案、所属分类或篇目，以及内容来源和使用授权；我方负责后端、Web 管理后台及接口，甲方另行安排小程序前端开发和接口接入。

## 1. 先准备目录，再填写题目

1. 整理正式题库所需的文学分类和文言篇目名称，交给后台管理员先建立目录。
2. 从后台重新下载最新模板，在“分类与篇目”页查找对应 ID，复制到题目中。不要用中文名称代替 ID，也不要自行猜编号；新建目录后应重新下载。
3. 只在首个“题库”工作表中填写正式数据，从第 2 行开始，一行一道题。填写完成后保存为 `.xlsx` 并交付。

项目内的 16 道演示题和 2 条“待补充篇目”占位不属于正式题库。正式目录、题目范围及答案应由甲方审核；本模板的示例也不应直接当作正式交付内容。

## 2. 工作簿怎么用

本次交付的 v1 模板包含以下四张表；后台重新下载的模板使用相同导入字段，参考示例可能不同。

| 工作表 | 用途 |
| --- | --- |
| 题库 | 第一行是固定表头，下面留空供填写正式题目；没有预填例题，避免误导入 |
| 填写说明 | 查看字段规则与填写提醒 |
| 例题参考 | 单独放置 4 行示例：文学单答案、文学 7 答案、文言字词、文言翻译；不参与导入 |
| 分类与篇目 | 查看目录 ID 和名称；正式填写以最新后台下载的目录及启用状态为准 |

“题库”第一行依次为以下 15 列，请保留名称和顺序：

```text
题目ID | 来源 | 分类ID | 篇目ID | 题型 | 标签 | 排序 | 题干 | 答案1 | 答案2 | 答案3 | 答案4 | 答案5 | 答案6 | 答案7
```

不要在表头上方增加标题，也不要在数据行中填写备注、合计或示例。不要合并单元格、插入空白分隔行或隐藏待排除的题目；隐藏行仍可能被读取，需要排除的内容应从“题库”表移走。

## 3. 每一列怎么填

| 列名 | 填写要求 |
| --- | --- |
| 题目ID | 必填，每道题固定且唯一。只用英文字母、数字、下划线 `_` 和连字符 `-`，最多 64 个字符，区分大小写；单元格设为“文本” |
| 来源 | 只填 `literature`（文学常识）或 `classical`（文言文），使用小写英文 |
| 分类ID | 文学题必填，从最新目录复制；文言题留空 |
| 篇目ID | 文言题必填，从最新目录复制；文学题留空 |
| 题型 | 只填 `fact`（常识）、`word`（字词）或 `translation`（翻译）；允许的搭配见下表 |
| 标签 | 可留空，最多 80 个字符。建议统一用“文学常识”“文言常识”“重点字词”“句子翻译”等简短文字；同类题保持一致 |
| 排序 | 填非负整数，建议用 `10、20、30…`，方便以后插题。数字越小越靠前；相同排序再按题目 ID 排列。留空按 `0` 处理，不填负数、小数、汉字序号或公式 |
| 题干 | 必填，填写展示给学习者的文字。答案位置使用 `{{0}}`、`{{1}}` 等标记，具体见下一节 |
| 答案1…答案7 | 按标记顺序填写答案，至少填写答案1。一个答案放在一个单元格内，不填 JSON 数组或带方括号的整串答案；未使用的尾部答案格留空 |

来源、题型和目录的组合如下：

| 题目类别 | 来源 | 题型 | 分类ID | 篇目ID |
| --- | --- | --- | --- | --- |
| 文学常识 | `literature` | 只能 `fact` | 必填 | 留空 |
| 文言常识 | `classical` | `fact` | 留空 | 必填 |
| 文言字词 | `classical` | `word` | 留空 | 必填 |
| 文言翻译 | `classical` | `translation` | 留空 | 必填 |

目录必须已经存在。停用目录可以保存题目草稿，但不能发布，正式交付请选用启用目录。

题目 ID 建议统一编号，例如 `lit-000001`、`cls-word-000001`、`cls-trans-000001`。这些前缀只是便于管理的建议，不是必须采用的分类规则。**修正同一道题时保留原 ID；新增另一道题时使用新 ID。** 不要因换文件、调整顺序或改题干而重编 ID。多位整理人员应先分好编号范围，避免重复。

## 4. 题干与答案一一对应

`{{0}}` 对应“答案1”，`{{1}}` 对应“答案2”，以此类推。括号使用英文半角花括号，编号从 `0` 连续开始；不要写成中文括号、`{{答案}}` 或从 `{{1}}` 开始。

例如：

| 题干 | 答案1 | 答案2 | 答案3 |
| --- | --- | --- | --- |
| 孔子是春秋时期{{0}}国人，{{1}}学派创始人，思想核心是{{2}}。 | 鲁 | 儒家 | 仁 |

每个填写的答案都必须在题干中有对应标记，同一个标记可以重复出现。不能在“答案1”和“答案3”之间空着“答案2”，也不能填了 3 个答案却只写 `{{0}}`。一个答案需要多行文字时，在同一单元格内换行，不要拆成几行题目。

模板默认保留“答案1”至“答案7”。超过 7 个答案时，在右侧连续增加“答案8”“答案9”……，最多到“答案32”；新增的列名不能跳号或重复，题干标记最多对应到 `{{31}}`。不用的尾部单元格保持真正空白，不填空格、“无”或破折号。

**翻译题采用统一写法：题干保留原句，换行后写“参考译文：{{0}}”，完整译文放在“答案1”，其余答案格留空。** 当前后台同样校验翻译题的答案标记，仅填原句而不写 `{{0}}` 会被拒绝。

翻译题干示例（以下两行放在同一个“题干”单元格）：

```text
青，取之于蓝，而青于蓝。
参考译文：{{0}}
```

对应“答案1”填写：`靛青从蓝草中提取，却比蓝草的颜色更青。`

## 6. 文件与内容限制

- 交付 `.xlsx` 文件，不使用 `.xls`、CSV、带密码的工作簿、Word、PDF 或图片代替。
- 每个文件不超过 **5 MiB（5,242,880 字节）**；“题库”表最多 **5000 行数据**，加表头共最多 5001 行。超出时按批次拆分，仍保持题目 ID 不重复。
- 删除末尾多余行、列及残留格式，避免被识别为超限表格；工作簿解压后的数据也不能超过 50 MiB。
- “题库”表不使用 Excel 公式。整理时使用过公式的，交付前复制并“粘贴为值”，检查结果仍是正确文字或数字；ID 列保持文本格式。
- 题干和答案使用文字。本版不增加图片、音频、视频、解析、难度、年份、发布状态、版本或权限等列；额外列会导致校验失败。补充来源或授权材料作为独立资料交付。
- 同一个文件内不能有重复题目 ID，也不能缺 ID。每一行须填写完整题目，不使用“只写 ID 和修改的某一列”的方式更新。

## 7. 导入后会发生什么

管理员上传文件后先查看预检结果，确认没有错误后，整批写入**草稿**；检查草稿和预览后，再由有发布权限的管理员发布。

| 文件中的题目ID与内容 | 处理结果 |
| --- | --- |
| 后台没有该 ID | 新建题目草稿 |
| 后台已有该 ID，内容有修改 | 更新这道题的草稿，保留固定 ID 和既有发布历史 |
| 后台已有该 ID，内容完全相同 | 显示“无变化”，跳过，不重复新增 |
| 同一文件内重复 ID，或任一行存在错误 | 整批不写入，修正后重新上传 |

更新已有题目时，空白标签会清空原标签，空白排序会按 `0` 处理，因此请交付完整数据。文件中没有出现的旧题不会自动删除或下架；需要撤下的题目应另列 ID 清单交给管理员处理。

预检结果有效期为 30 分钟；其间题目被新增、修改、发布或下架，确认导入时可能提示冲突，需要重新上传预检。导入完成不会自动发布，也不会直接覆盖已发布答案。当前小程序尚未接入后台，正式前端接入由甲方开发团队根据接口另行完成。

## 8. 交付前检查

1. 正式题目和答案已由甲方校对，内容来源及使用授权材料已准备。
2. 使用当前模板，第一张“题库”表的表头未改名，下面只有正式数据；参考例题没有混入。
3. 目录已建立，分类 ID、篇目 ID 来自最新后台模板，文学与文言归属没有混填。
4. 题目 ID 唯一、稳定且为文本，所有行均填写完整；多文件之间也没有误用同一 ID。
5. 题干标记与答案列对应，答案列之间没有漏填，翻译题包含“参考译文：{{0}}”。
6. 文件为无密码的 `.xlsx`，没有公式、合并单元格、额外列或超限行。

建议按 `正式题库-批次01-20261002.xlsx` 这样的名称交付，并附上本批内容范围、整理人和校对人。需要替换已交付题目时，说明修改的 ID 并提交完整行，便于管理员核对预检差异。

## 9. 模板验证记录

本模板已使用现有后台的真实 XLSX 导入器验证。四行参考例题复制到“题库”后均通过预检；确认导入只生成草稿，重复导入全部跳过。预检未留下数据更新，验证使用独立测试数据库。建议甲方先交付 10～20 道正式样题，确认内容和显示方式后再整理全量题库。
