## 2. 打开项目并保护旧数据

在项目文件夹打开PowerShell，确保能看到`backend`目录。下面命令都从项目根目录执行。已有数据库时先停止当前后端进程；终端运行着`start.ps1`时按Ctrl+C。

**已有后端数据：先备份，再升级。** 不要直接删除数据库或`.env`重新安装。使用已有虚拟环境执行：

```powershell
$localBackupStamp = Get-Date -Format 'yyyyMMdd-HHmmss'
.\backend\.venv\Scripts\python.exe .\backend\manage.py backup_database --output ".\backend\.local\backups\before-local-$localBackupStamp.sqlite3"
```

该示例适用于当前本机SQLite；工具创建一致快照并拒绝覆盖旧文件。若时间相同导致目标已存在，使用另一个新文件名，勿删除原备份。备份含账户和业务历史，只保存在受控私有目录；已有加密数据还依赖原加密密钥，不能丢弃或换一把新钥匙代替。PostgreSQL备份／恢复按[运维手册](生产部署与运维手册.md)操作。

备份完成后执行初始化。新电脑没有旧数据时可直接从此步开始：

```powershell
.\backend\setup.ps1
```

它安装锁定依赖、执行已有迁移、初始化题库组／业务组和单商品；保留已有题目、管理员、价格及权限。首次会提示自行建立管理员密码，没有默认密码。已有`.env`会保留，因此早期缺少的学员／微信／支付字段还需要下一步补齐。演示16题是草稿，不是甲方正式收费题库；重复初始化不覆盖手工修改。

如果备份或迁移报错，先处理原因，保留原库及原密钥，不继续手工改商业表。新模块不会自动给已有用户增加权限，也不会自动把已有组扩权。

## 3. 配置已经确认的账号

将下面`你的AppID`、`你的OfferID`替换为用户确认的真实编号，只在本机终端操作。两者不是秘密，但本项目公开文档与PR仍只保存脱敏例子。不要使用游客AppID或旧账号的编号。

```powershell
.\backend\.venv\Scripts\python.exe .\backend\scripts\configure_local.py --app-id "你的AppID" --offer-id "你的OfferID" --confirmed-filing --confirmed-virtual-payment --confirmed-apple --confirmed-member
```

`--confirmed-*`记录的是用户提供的备案、虚拟支付、Apple和成员确认。工具不会登录微信后台替你验证，不会把人工确认变成支付成功、商品同步或上线验收。

若此步提示`SECRET_MISSING`并退出非0，账号档案可以已保存，但必要秘密仍不齐；这是“只完成标识准备”，不是已就绪。继续下一步私有录入，勿据此打开销售。

实际标识进入私有`backend/.env`及`backend/.local/wechat-account.json`；档案只有`schemaVersion`、`appId`、`offerId`与`platformConfirmed`，不含秘密。支付开关保持关闭。已有另一AppID、存在不安全状态或配置文件发生并发变化时，工具拒绝静默切换，按安全提示处理，不强行覆盖。

微信openid属于具体AppID。改一个AppID不能迁移学员、Bearer、订单或权益，也不能宣称旧Bearer自动失效；本轮不做账号转移。使用选定小程序取得的新登录code，不混用其他小程序身份。

## 4. 用隐藏输入补齐秘密

秘密由有权限的人员在本机交互终端录入，不发到聊天、不写进命令参数或Git，也不传给学员前端。在刚才命令末尾增加`--fill-missing-secrets`：

```powershell
.\backend\.venv\Scripts\python.exe .\backend\scripts\configure_local.py --app-id "你的AppID" --offer-id "你的OfferID" --confirmed-filing --confirmed-virtual-payment --confirmed-apple --confirmed-member --fill-missing-secrets
```

按提示隐藏输入AppSecret、支付所用环境的AppKey及消息安全配置；输入时看不到字符是正常现象。已有秘密保留；主动替换单个字段时使用`--update-secret FIELD`，可用字段以工具`--help`为准，秘密本身仍由隐藏输入提供。没有交互终端时工具拒绝录入，不会改成明文输入。

会话加密密钥只在确认不存在需要原密钥解密的数据时补生成，已有密钥不会自动轮换。如果提示已有加密会话／令牌缓存却缺少原密钥，先恢复原密钥，不生成新的来覆盖。Django密钥及其他无关配置同样保留。

若甲方暂未提供全部秘密，可以只保存账号标识，下一步诊断会明确报告缺项。没有秘密不能真实微信登录或付款，不能用假密钥／假成功接口填补。

## 5. 运行只读离线诊断

```powershell
.\backend\.venv\Scripts\python.exe .\backend\scripts\check_local_readiness.py --json
```

该命令转到`manage.py check_local_readiness --json`。它不联网、不发权、不写业务数据，不临时打开支付开关；输出只含`checks`数组中的固定检查码、状态及安全提示，不显示秘密、摘要、Bearer、原码或平台订单正文。

| 状态 | 看懂提示后怎么做 |
| --- | --- |
| `ready` | 该项本机检查通过；不等于真实微信或支付已成功 |
| `missing` | 缺配置、迁移、管理员、权限或商品等，按提示补齐 |
| `blocked` | 存在不安全或冲突状态，先解决，勿强行覆盖配置／密钥 |
| `pending` | 需要平台商品核对、真实设备、前端、HTTPS等外部证据，离线工具不能代验 |

有`missing`或`blocked`时退出非0；仅剩外部`pending`不单独使命令失败。退出0只说明本次离线检查执行结果满足本机要求，不能当作“可以正式上线”。本机SQLite可运行，但它不证明交易行锁／并发正确；已有PG16 CI证据与实际部署数据库仍是不同事项。

## 6. 启动后台并检查已有功能

```powershell
.\backend\start.ps1
```

打开`http://127.0.0.1:8000/admin/`，用自己的管理员账号登录。按以下顺序做小范围检查，正式题库和真实业务数据不要用作随意试验材料：

1. **题库：** 下载XLSX模板，导入少量测试题，先看预检，再确认草稿；发布后学员内容接口才可读取。修改草稿不改变已发布内容，下架后不可读取。导入错误整批不写入。
2. **学习配置：** 设置每页题数1～100；同篇目字词／翻译共享免费集合。首次保存需要`content.add_learningconfiguration`，以后修改需要`content.change_learningconfiguration`；这两项由可信管理员按职责授权，不默认给普通编辑／发布人员。
3. **后台分权：** 查看、编辑、发布分别验证；业务角色沿用“业务查看、学员启停、商品运营、激活码管理、权益撤销、支付核查”。启停人员不能编辑管理员权限，核查人员不能手改订单为已付。
4. **商品：** 后台单商品初值10元、永久权益；OfferID不是平台商品编号。核对平台永久权益商品、金额及发布状态后，才由商品运营人员在后台预览／确认同步。改价后需重新同步，本轮不因人工账号确认自动标记。
5. **激活码：** 用专门测试批次验证一次CSV下载、领取确认、启用、禁用／作废及撤销影响预览。原码CSV仅私有保管。学员实际兑换需登录；成功后永久，已激活不消耗另一新码，撤权后已用码保持已用。
6. **学习／随机／续学：** 接入真实学员后验证本人状态、收藏／掌握、双设备409、失权展示、固定轮次及续学；管理员Cookie不能代替学员Bearer。具体请求在[联调手册](学员接口联调手册.md)。

前四项与管理操作可先本机检查；完整学员流程需甲方前端取到选定AppID的真实`wx.login`code，或使用隔离的自动化测试验证代码路径。不得在运行服务新增假登录／假付款成功入口。已有自动化回归使用临时库，不冒充用户真实渠道验收。

## 7. 本机准备后怎样交给甲方前端

交接[学员联调手册](学员接口联调手册.md)与[OpenAPI](api/student-v1.openapi.json)。甲方前端按`wx.login → Bearer → config／试学 → 权益／商品 → 订单／支付准备 → 后端查单`接入；后台人员不用替甲方重做页面。

准备支付前先`wx.checkSession`，必要时重新`wx.login`。后端Bearer默认7天不证明微信session_key仍有效。支付参数签名字符串必须原样传给`wx.requestVirtualPayment`；客户端success、cancel或超时都不能直接发权／释放占位。购买、兑换和学习写入按正式契约带幂等键，冲突409时读取当前状态处理。

本机`127.0.0.1`只供电脑本身访问，真机不能把它当后端服务器，微信平台也不能向它推送真实回调。离线安全信封检查或测试AES消息不证明实际回调已送达。甲方前端／真实设备和后续可访问HTTPS环境就绪后，再单独验证登录、Android／iOS付款、发货、退款与补偿任务。

iOS仅正式环境0且金额至少100分，平台Apple已开仍须实际设备验收。本轮不启用iOS销售，也不主动联网查单／发货。Apple退款问询保留已批准的官方不确定兜底，不自行新增同意／拒绝策略。实际公网部署、平台类目／商品操作和甲方前端验收不由离线工具代替。

**现在可以按顺序补齐本机资料：**

1. 在本机交互PowerShell隐藏填写缺失秘密，不发到聊天。已有账号编号可直接从私有档案读取，避免再次手填：

```powershell
$localWeChatProfile = Get-Content -LiteralPath '.\backend\.local\wechat-account.json' -Raw | ConvertFrom-Json
.\backend\.venv\Scripts\python.exe .\backend\scripts\configure_local.py --app-id $localWeChatProfile.appId --offer-id $localWeChatProfile.offerId --fill-missing-secrets
```
